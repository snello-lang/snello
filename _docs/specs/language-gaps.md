# What the language is missing

Status: written 2026-11-08 for review. The list of gaps was agreed on 2026-11-08 on one condition: every feature keeps the memory safety the borrow checker enforces, and none brings in a garbage collector. Decided the same day: no zero values, reflection at compile time, no `switch`, no labels, and defaults on struct fields with no parameter defaults and no overloading. The other rows each carry a recommendation, reviewed in its task's design. The rows are the tasks of stage 11, `stage-11-language-whole.md`, planned the same day.

## How to read it

`standard-library-gaps.md` judged the library against its rule. This document judges the language and its tools against what a programmer expects of any standard programming language at the bare minimum, with Go, Rust and Swift as the reference: three languages in wide use, one with a collector and two without, which between them have settled what a working programmer reaches for. A row is a gap when all three have the feature, or when Snello's own design needs it, and Snello has neither the feature nor a decision against it. Matching one of the three is never the reason; Snello sets its own course, and a row says what fits Snello.

Each row gives what the three languages do, a recommendation, how the recommendation stays memory safe without a collector, and the decision. The condition is the same for every row:

- **Memory safety** holds when the feature is checked by the rules the borrow checker already enforces: one owner, `ref` and `mut` borrows that do not outlive their owner, moves the checker tracks, `Drop` on every exit. A feature that adds only refusals is safe by construction, since the checker then accepts fewer programs, never more.
- **No collector** holds when every value the feature makes has one owner and is freed by its `Drop` at a point the compiler knows, with no tracing, no hidden reference counting, and no metadata kept alive at run time for the feature's sake.

What stays out by design and is not a gap: a garbage collector; runtime reflection that reads or writes a value behind the checker's back; `unsafe` and raw pointers, since C is reached through a package that binds it (`08-packages.md`); `nil`; exceptions, since errors are `Result` values; class inheritance, since traits carry defaults and fields; `async` and `await`, since a task is an ordinary call under `spawn`; and macros a program writes, since the derived traits cover what they are mostly used for.

## The language

| Gap | Go, Rust and Swift | Recommendation | Memory safe, no collector | Decision |
|---|---|---|---|---|
| Null and empty values | Go gives every type a zero value: a nil pointer, map, channel, function or interface is a zero that panics on use. Rust has no zero values: a variable is assigned before it is read, and a default is opt-in through `Default`. Swift checks that every variable is assigned before use, and only an optional is nil. | A type has no zero value when it implements `Drop`, since it owns something its zero would not, a cell, a lock, a file; when it is a type parameter; when it is a pointer, channel, function or trait value; or when it holds one of these. The checker refuses every way of making that zero: `var x T` with no value, a struct literal that leaves such a field out, an array literal shorter than its length, `make([]T, n)` (while `make([]T, 0, n)` stays), a read `m[k]` of a map of such values, with a message naming `m.Get(k)`, and `take`, refused already. A builtin `replace(place mut T, v T) T` moves a value out of a place and leaves `v` in it, for every type. The `sync` and `rc` handles then exist only from their constructors, and their empty-handle panics cannot be reached. Today `var p *int` compiles to a null that `*p` follows, found 2026-11-08. | Refusals only, so the checker accepts fewer programs; a null can no longer be written, and every `Drop` runs on a value a constructor or a literal made. `replace` leaves a valid value in the place, as Rust's `mem::replace` does. Nothing is allocated. | Decided 2026-11-08: its own task, the first of the stage. With it, `strings.Repeat` returns `string?`, `WaitGroup.Add` and `Done` return `false` for a count that would go below zero, and `arena.Remove` drops its `Expect`, so that the library panics on no mistake a caller can make |
| Reflection, to encode and print a program's own types | Go's `reflect` reads and writes any value at run time, and `encoding/json` is built on it with struct tags. Rust has no reflection at run time; `serde` derives the code at compile time with a macro. Swift's `Mirror` reads a value at run time, and `Codable` is written by the compiler for a type that lists it. | Swift's `Codable` in Snello's form: a standard trait the compiler derives for a type that lists it, as it derives `Eq`, `Hash` and `%v` now. Two methods: one hands each field to a visitor by name as a `ref`, the variant's name first for an enum; the other builds the value from a source by asking for each field by name, and returns a `Result`, a missing field being an error. A JSON or CSV library outside the compiler then encodes and decodes any type that lists the trait, and a test fake is a library over the same trait. How a field is renamed, Go's struct tag, is decided in the task. | The visitor receives shared borrows only, so nothing is written through it; the value is built by a literal that names every field, so no zero is made. The code is generated for the types that list the trait, and nothing is kept at run time. | Decided 2026-11-08: at compile time, never at run time; its own task, after the one on zero values |
| `switch` | Go has `switch`. Rust has only `match`. Swift's `switch` is a pattern match that must be exhaustive. | No `switch`: `match` is the one way to branch, on a value, checking that every case is covered, and, written with no value, on conditions, `match { x > 0 => ..., _ => ... }`, the first that holds, as Go's tagless `switch`, Kotlin's `when` and Lisp's `cond` do, the arm `_` required and last. Nothing in the library, the examples or `lib/` uses it, and neither backend compiles it. The word stays reserved, and using it is an error that names `match`. | Nothing to check: a construct goes. | Decided 2026-11-08: dropped, and `match` with no value added in its place, task 11.1; a guard, which runs whether or not its arm is taken, may move nothing, a hole the task found and closed |
| A program's own variadic functions | Go's `func f(xs ...T)` receives a slice, and `f(s...)` passes one. Rust has no variadic functions but C's, and uses macros instead. Swift's `T...` receives an array. | `func Sum(xs ...int)` receives an owned `[]int`, the arguments moved into it; `func Show(xs ...ref T)` receives a slice of borrows, as the library's `...ref any` does today; `Sum(s...)` passes a slice. | The owned form moves each argument into a slice the function owns and drops; the borrowed form lends each argument for the call alone, as a `ref` parameter does. | Gap agreed 2026-11-08; the recommendation for review |
| Constant expressions | Go evaluates constant expressions at compile time, `const KB = 1 << 10`, with `iota`. Rust's `const` items take expressions, and `const fn` runs at compile time. Swift guarantees no evaluation at compile time beyond literals. | A `const` takes an expression of literals, other constants, the arithmetic, bitwise and comparison operators, and conversions between number types, folded by the checker; an array length is a constant, `[N]int`. No `iota`, since an `enum` names its cases, and no function run at compile time. | Folded at compile time; nothing is allocated or owned. | Gap agreed 2026-11-08; the recommendation for review |
| A generic trait as a type | Go's instantiated generic interface is a type. Rust's `dyn Iterator<Item = i32>` is a trait object. Swift's `any Sequence<Int>` is an existential. | `Iterator<int>` as a type when every type argument is given, a trait value as `Shape` is today; `[]Iterator<int>` holds iterators of any type. Chapter 11 says it waits for a program that needs one: a program that keeps iterators of different types in one slice is one. | The same as a trait value today: one owner, a box and a method table, freed by its `Drop`. | Gap agreed 2026-11-08; the recommendation for review |
| `Eq` on tuples and options in generic code | All three compare tuples and optionals whose parts compare. | Both backends: `expect.Equal` on a tuple or an option, found in task 9.6. | No ownership changes: equality reads its operands. | Task 9.7 |
| Labeled `break` and `continue` | Go has labels, Rust has labeled loops, `'outer: for`, and Swift has labeled statements. Python has none: it declined them in PEP 3136, the need being rare. | No labels, as the syntax note has it: `break` and `continue` mean the innermost loop. Leaving several loops at once almost always means found or give up, and a small function that `return`s says so, with a `T?` result and `??` to make it cheap; a search over a grid is `for r, row := range grid { for c, v := range row { if v == want { return Some((r, c)) } } }`. One meaning for `break`, nothing new to learn. | Nothing to check: no construct is added. | Decided 2026-11-08: no labels; the syntax note stands |
| Optional settings: default values and overloading | Go has neither, and a zero cannot be told from a setting left out, so libraries write builder chains or pointer fields. Rust has neither, and builder types; it accepted default field values in 2024 (RFC 3681) because builders weigh too much. Swift has default parameters, overloading and default field values. Zig has default field values, and options structs are its idiom. | Defaults on struct fields, not on parameters: `struct ListenOptions { port int = 8080; backlog int = 128 }`, a constant expression each. A literal that leaves a field out takes its default; a field with none takes its zero value, or is refused when its type has none, the rule of the first row. A function takes its settings as a struct: `net.Listen("localhost", ListenOptions{backlog: 16})`, every setting named, in any order, any of them skipped, with no new call syntax and nothing lost when the function is a value, where parameter defaults are trailing only, cannot skip one and are lost through a function value. A declared default makes a setting left out a value of its own, which Go's zero cannot be. No overloading: a literal takes its type from its context and type arguments are inferred from the arguments, so one name with several signatures makes `Max(1, 2)` and `f := Max` ambiguous; a generic function with a bound, `Max<T: Ord>(a T, b T) T`, and distinct names where the work differs, `ParseInt` and `ParseFloat`, do what overloading is used for. Inferring the literal's type from the parameter, `net.Listen("localhost", {port: 9000})`, is a separate question, left for later. A trait field keeps no default, as the syntax note has it. | A default is a constant, a string one a literal that owns nothing; every field is set before the value exists, and nothing is allocated. | Decided 2026-11-08: default field values, after constant expressions and the rule against zero values; no parameter defaults; no overloading |

## The runtime and the tools

| Gap | Go, Rust and Swift | Recommendation | Memory safe, no collector | Decision |
|---|---|---|---|---|
| A stack trace on a panic | Go prints every goroutine's stack. Rust prints the panicking thread's with `RUST_BACKTRACE=1`. Swift's runtime prints a backtrace on a crash. | The panicking task's stack, one line per frame with the function and its file and line, from a table the compiler writes of each function's name and lines, walked by the runtime over the frame pointers before the unwinding runs the drops. | The tables are read only; the walk allocates nothing, and the unwinding runs every `Drop` as it does today. | Gap agreed 2026-11-08; the recommendation for review |
| Debugger information | All three emit DWARF, read by Delve, gdb and lldb; profilers such as `perf` and Instruments read the same. | The LLVM backend emits DWARF line tables and variable locations in a `-debug` build, and the C backend writes `#line` directives, so lldb and gdb step through Snello source. | Information in the binary only. | Gap agreed 2026-11-08; the recommendation for review |
| Code for one platform | Go chooses files by their names, `_linux.go`, and by `//go:build` lines. Rust has `#[cfg(target_os = "linux")]`. Swift has `#if os(Linux)`. | Go's file names: `poll_linux.snello` and `poll_darwin_arm64.snello` are built only for their target. No attribute inside a file. Windows, which stage 10 decides, needs it, and so does a library binding C that differs between systems. | The choice of files only. | Gap agreed 2026-11-08; the recommendation for review |
| Building for another platform | Go sets `GOOS` and `GOARCH`. Rust takes `--target`. Swift takes a Swift SDK for the target. | `snello build -target linux/arm64`: LLVM emits for the target, the runtime is compiled for it with the C compiler's own cross target, and the platform files of the row above are chosen by it. | Building only. | Gap agreed 2026-11-08; the recommendation for review |
| Dependencies by version | Go modules are fetched by version through a proxy and checked against a checksum database. Cargo fetches crates from crates.io and pins them in `Cargo.lock`. The Swift Package Manager fetches from git and pins in `Package.resolved`. | `require NAME URL VERSION` beside the local `require NAME DIR` of today: a module fetched from a git repository at a tag, its hash recorded in a lock file beside `snello.mod`, and checked on every build, so a dependency cannot change under a program. A registry comes later, if ever. | Building only. | Gap agreed 2026-11-08; the recommendation for review |
| `snello doc` | `go doc` and pkg.go.dev; `rustdoc` and docs.rs; DocC. | `snello doc PKG` and `snello doc PKG.NAME` print the exported declarations and their comments, from the checker's view of the package; pages for the web later. | A tool only. | Gap agreed 2026-11-08; the recommendation for review |
| Running programs and catching signals | Go has `os/exec` and `os/signal`. Rust's `std::process::Command` runs a child, and catching a signal is left to a crate. Swift's Foundation has `Process`, and signals come through Dispatch. | In the library: `os/exec`, a command run as a child whose handle is owned and waited on through the scheduler's poller, its pipes an `io.Reader` and `io.Writer`; and `os/signal`, the interrupt and terminate signals delivered as values on a channel. A signal handler cannot be safe Snello code, and the runtime owns the threads, so a library outside could not write it. | The child, its pipes and the channel are owned handles, closed by their `Drop`. | Gap agreed 2026-11-08; the recommendation for review, as a task of stage 9 beside task 9.11 or of the new stage |

## The order

The order of stage 11's tasks, `stage-11-language-whole.md`, around the rest of stage 9:

1. Task 11.1, no `switch`, small and first.
2. Task 11.2, no zero values, before the rest of stage 9, since it changes `strings`, `sync`, `rc` and `arena`, which tasks 9.7 and 9.13 build on.
3. The rest of stage 9, with the rule in place; task 11.14, `os/exec` and `os/signal`, may run beside task 9.11.
4. Tasks 11.3 to 11.5: constant expressions, default field values on them, and variadic functions.
5. Tasks 11.6 and 11.7: reflection, then a generic trait as a type.
6. Tasks 11.8 to 11.13: stack traces and debugger information, platform files and cross building, dependencies by version and `snello doc`, all before the release of stage 10.
