# The language server

Status: built. Diagnostics, hover, definition, the outline, the workspace's symbols, references, rename and completion, and every decision of the next section but the standard library's, which section 10 says why. Formatting and the editor extension are tasks of their own.

An editor learns what a program means from a language server: a process it starts beside itself and talks to over the Language Server Protocol, JSON-RPC 2.0 messages on the server's standard input and output, the one protocol every editor of note speaks. Snello's server is part of Snello's command, `snello lsp`, built from the compiler's own packages, so that what the editor shows is what `snello check` says, word for word.

## What Snello's server is for, and what it will not carry over

A developer opens a file and the editor knows it: its errors, its names, its uses, without a setting, an install of its own or a restart. That is the bar, and every precedent misses it somewhere, mostly because of its language's own history. Snello's design leaves that history out, and the server is built on what Snello has that the others do not.

**One checker, never a second.** A server that runs a front end of its own, as `rust-analyzer` does, shows errors the build does not and misses some it does, and leans on running the build beside itself to make up for it. Snello's server checks through the compiler's loader and checker, so the editor and `snello check` agree on every program, message for message, and nothing runs beside it.

**One binary, no version to match.** A server installed apart from its compiler, as Go's `gopls` is, is one more thing to install, and must be kept at a version that understands the compiler's. Snello's server is a command of `snello`, `snello lsp`: the server is the compiler it ships with, present wherever `snello` is, and installs nothing.

**No settings.** Go's server has build flags, environment, directory filters and a workspace file to say what a workspace is; clangd needs a compilation database written by the build. Snello's server has none and asks for none: a module is a directory with `snello.mod`, found as the importer finds it, with no name to configure; a file's platform is in its name, never in a line inside it; the standard library is in the compiler. What a server would be told, Snello's already knows.

**Every platform's files, as they are.** A Go file for another system, or under a build tag, is outside the build configuration `gopls` checks, and the editor says no package holds it: since its version 0.15 the server opens a configuration of its own for a file of another system, but a file under a tag the project defines still waits for the developer to set the tag in the server's settings, and checking a project under several configurations at once is a long-standing request of Go's server. A Snello file's platform is its name, `poll_windows.snello`, so the server knows each file's platform without being told.each open file is checked for its own platform, its package with it, the host first; an error of another platform's check is labelled with it, `on windows/amd64: …`. References and rename already search every platform's files.

**A method's dispatch is in its declarations.** A Go method is tied to every interface a value of its type is assigned to, anywhere in the program, since Go's interfaces are satisfied implicitly; its server must look at the whole program to rename a method, refuses to rename one from the type's side, and has had renames that did not reach every implementation. A Snello type lists its traits after `impl`, and a trait the traits it refines after its colon, so the methods that share a dispatch are known from declarations alone. A method is renamed with every method it shares a dispatch with, in one edit: the trait's method, each type's that implements it, each trait's that overrides it, from whichever of them the rename begins. It is refused only when one of them is not the editor's to change, a trait of the standard library or of a required module, and the refusal names it.

**The standard library is checked with every check, until the checker can share it.** The library is in the compiler and cannot change while the server runs, so checking it once a session and sharing it among the checks would cost a keystroke the developer's packages alone. It was built and measured, five times faster and a sixth less memory, and taken back: the checker keeps what a check works out of an imported package on that package's objects, so a library shared among checks either holds every check it served or, taken back after each, loses what its own checks made. Section 10 says what the checker needs before the library can be shared.

**What the developer types is answered at the place it is typed.** Completion needs the names visible at one position. The checker is given that position and records, as its walk resolves the name there, what is visible, and nothing for any other place; a local declared further down is not visible because it is not declared yet when the walk passes. Section 9.

**Nothing of it in a program.** The server is the compiler's own packages run beside the editor; a Snello program's binary carries the runtime and the standard library alone, so the server changes nothing of a program's memory safety, its ownership and borrowing, or its having no garbage collector: it reports the borrow checker's errors as the compiler does, and the compiler emits the same program, byte for byte, with the server's changes or without them.

**No number without a measurement.** A limit, a cache or a shortcut is in the design because a measurement asked for it, and the note gives the measurement; none is taken from another server because that server has it.

## 1. The process and the protocol

`snello lsp` reads messages from standard input and writes them to standard output, each a header, `Content-Length: N`, a blank line, and N bytes of JSON; a `Content-Type` header, which the protocol allows, is read and ignored. Logs go to standard error, which editors show in their output panes, never to standard output, which is the protocol's.

Three packages under `lsp/` hold it, each with its tests, as `compiler/` holds the compiler: `lsp/jsonrpc` the framing and the messages, a request with an id, a notification without, a response with a result or an error; `lsp/protocol` the protocol's types, only the ones the server uses, named as the specification names them; and `lsp/server` the server itself. `snello lsp` is the command: it runs the server over its standard input and output and exits with the code the protocol asks for, 0 after a `shutdown` and an `exit`, 1 after an `exit` alone or a closed input. It is a command of `cmd/snello`, `lsp.go`, beside `check` and `doc`, and takes the flags an editor's client passes, `--stdio` and `--clientProcessId`, and needs neither.

A request is answered once, in the order its work finishes, which for this server is the order it came in. A request the server does not know is answered with the protocol's `MethodNotFound`; one before `initialize` with `ServerNotInitialized`; a notification the server does not know, and every `$/` notification, `$/cancelRequest` included, is passed over, as the protocol allows, since nothing here runs long enough to be worth cancelling.

## 2. What the server says it does

`initialize` is answered with the capabilities of what is built and no more, so that an editor never asks for what the server cannot give:

- `textDocumentSync`: open and close, incremental changes, and saves without their text;
- `positionEncoding`: UTF-8 when the editor offers it, UTF-16 otherwise (section 5);
- `hoverProvider` and `definitionProvider` (section 7);
- `documentSymbolProvider`, `workspaceSymbolProvider`, `referencesProvider`, and `renameProvider`, with `prepareProvider` for an editor that asks before it renames (section 8);
- `completionProvider`, with `.` and `"` as the characters that ask for it (section 9);
- `serverInfo`: `snello` and the compiler's version.

The server reads no settings: `initializationOptions` and `workspace/didChangeConfiguration` are passed over, since nothing a developer could set is not already known from the files.

The diagnostics are pushed, `textDocument/publishDiagnostics`, which every editor takes; the pulled form of protocol 3.17 asks the editor to poll, and adds nothing a push does not give a server whose checks are this quick.

## 3. Documents

The server keeps the text of every document the editor has open, by its URI, with the version the editor gave it. `didOpen` stores it; `didChange` applies each change in turn, a range replaced by its text or, with no range, the whole text replaced; `didSave` changes nothing, since the editor's text is already the file's; `didClose` forgets the document, and the next check reads the file from disk. A change is applied to the bytes the server holds, its range converted from the editor's positions to byte offsets in the text as it stands before that change, as the protocol orders the changes of one notification.

A package is checked from these buffers where a file of it is open and from the disk elsewhere: the loader reads every source through a function the server gives it, `importer.Options.Read`, `Load.Read` and `Importer.Read`, which answers from the open documents first. Each reads through `os.ReadFile` when no function is given, as every command of the compiler does. The read reaches the packages the open file's package imports too, so a library package edited in one window and imported in another is checked as it stands in the editor. A file that exists only in the editor, created and not yet saved, joins its package when it is saved, since the package's files are listed from the directory: a save is checked as a change is, which also picks up a file of an imported package saved from another editor.

The module's requirements are resolved from the module cache and the lock file alone, `Module.ResolveCached` through `importer.Options.Cached`, never as a build resolves them: a build fetches a module the cache lacks, fetches again a copy whose files changed, hashes every module, writes `snello.lock`, and removes it when nothing is required by version. A check as the developer types does none of it: it would reach the network, and write the program's files, on every keystroke. A required module the cache does not hold is an error naming `snello fetch`, which puts it there; a cached copy is held to the lock file's record, and its files are not hashed, which the build does.

## 4. Checking

A document's package is its directory's, checked as `snello check DIR` checks it, through the one function both use, `importer.CheckDir`: as a program when its package is `main` or the directory is a module's root, as a library under the module's rules otherwise. The package's test files are then checked as `snello test` loads them: the test runner's plan, `testrun.PlanDirFrom`, says whether they are a main package's, the package's own or an external test package's, `NAME_test`; a main package is checked with its test files, and a library by the import path its tests are reached at, `importer.CheckTests`, so that every error keeps the test file and the position it names. The runner `snello test` generates is not checked: an error there would name a file the developer never sees.

A directory in which more than one file declares `main` holds programs of one file each, as `examples/tree/` holds two, each built by `snello build FILE`; the server checks each such file alone, as `snello check FILE` does, where `snello check DIR` would report the second `main` as a redeclaration. The rule follows how the programs are built, and no file of a package of several files declares `main` but one.

**Every open file for its own platform.** A package is checked for the host, and, for each open file of it the host's build does not choose, for the first platform whose build does, in the order `snello` lists its platforms; an error of a check for another platform than the host's is published with the platform before its message, `on windows/amd64: undefined: x`, so that the developer sees which build it breaks. A package none of whose open files is another platform's is checked for the host alone; a package all of whose files are other platforms', `name_windows.snello` and `name_linux.snello` open on a Mac, reports what `snello check` says of it for the host, that every file is for another platform, beside each platform's own check.

Every package with an open document is checked again after every change, whole, from its files to its imports, the standard library's included: about 2 ms a package for the packages under `examples/`, tests included, on an eight-core arm64 Mac (section 11), so a keystroke's check is done long before the next. The whole package, and not the edited file alone, because a change to one file can break another of its package, and the measurement shows the whole is cheap enough.

## 5. Positions

The compiler's position is a line and a column in bytes, both from 1. The protocol's is a line from 0 and a character in the units the editor and the server agreed: UTF-16 code units by default, the units of JavaScript's strings, or UTF-8 bytes, or code points, when the editor offers them in `general.positionEncodings` (protocol 3.17). The server takes UTF-8 when offered, since it is the compiler's own unit and needs no conversion, and UTF-16 otherwise, which every editor understands. A column in UTF-16 is counted over the line's text up to the byte: a character of the Basic Multilingual Plane is one unit, one beyond it, an emoji, two. A tab is one unit, as the protocol counts it.

## 6. Diagnostics

Every error the parser or the checker reports becomes a diagnostic of severity Error, with source `snello` and the compiler's message, on the file the error names. Its range starts at the error's position, its byte offset converted to the protocol's line and character, and covers the word there, an identifier, a keyword or a number, or the one character there when it starts none, since an editor underlines a range; at a line's end or the text's end it is a point, which an editor marks at the end of the line. The parser stops a check: a file that does not parse reports its syntax errors alone, and the checker's appear once it parses, as `snello check` reports them.

An error without a position, a module file that does not parse or a package of no files, is reported on the first line of every open document of the package, so that it is seen where the developer is; one of the tests' alone, on the open test files. A package that imports one that does not compile reports it as the checker does, on the import, with the imported package's errors in its message; the imported package's own file shows its errors once it is open, since its own check then names them. The loader keeps such a package's errors whole behind the message, so that a check of the package itself finds each one's file and position. A file's diagnostics are the union of what every check reports on it. A check that reports nothing on a file it reported on before publishes an empty list for it, which clears the editor's marks; closing a document publishes its file's diagnostics again from the remaining checks, and nothing for a file no check names.

## 7. Hover and definition

Both start from the place under the cursor in what the file's last check left, its view. A check is handed every file it parses, the program's and every package's it imports, through `importer.Options.Parsed`, as each is parsed, a file with errors too; once the check ends, its view keeps the checker's `types.Info` on the names and expressions of the package's own files and those files' syntax, every file it parsed, which a position is resolved against, the sources it read, and the type each function of a type belongs to, and lets the rest go: what the check knew of its imports' insides no request reads. A package's files are answered from the check of its sources, its test files from the check of its tests. A request about a document waits for the check of the changes that came before it in the same batch of messages, so that it is answered on the latest text.

The place holds the identifier whose letters cover the cursor, or that ends there, where a cursor after a word stands, found by `ast.Inspect`; `types.Info.Defs` or `Uses` gives the object it declares or uses. With no identifier there, the token there, scanned from the text, belongs to the innermost node that records it as its own: the operator of a binary expression, the parenthesis of a call, a literal. Its type, from `types.Info.Types`, is the hover; a place with neither has none.

**Definition** is the object's position, resolved to its file. A load parses every file into one `token.FileSet`, the program's and every package's it imports, so that a position names one file of the whole program, which a definition in another package needs; a set of each package's own, as the loader had, gave two packages the same positions. A position a file does not hold resolves to no line, where it was read against the wrong file's lines. A method called through a trait bound is the method of the trait, which is what the checker gives the type parameter, so the definition lands on the trait's declaration. A name the language declares, `int` or `len`, has no definition. A name of the standard library is declared in a file the compiler holds and the disk does not: the server writes the file to `std/VERSION/PATH` in Snello's cache directory, the one `SNELLO_CACHE` names or `snello/` in the user's cache, once for each version of the compiler and again when its text differs, through a file renamed into place so that no reader finds it half written, and points the editor there. The copy is read-only, since an edit to it changes nothing, and its name must be a path under `std/`. An editor that opens it checks nothing: a document under the copies of this version is the library's package, answered from a check of the package in the compiler, with its privileges, and reports no diagnostic, and a copy of another version's is neither checked nor answered. With the cache off, the request is answered with an error that says so. The range of a definition is the token there, the whole path of an import for a package's name.

**Hover** is the declaration as the checker types it, `types.ObjectString`: a function with its type parameters' bounds and its parameters' names, `func Largest<A: Shape, B: Shape>(a ref A, b ref B) f64`; a method with its receiver; a function of a type with its type, `func Point.Origin() Point`, which the server reads from the declaration, since the function's object does not keep it and keeping it would grow every function object by a word; a struct, an enum and a trait with the traits after `impl` or the colon and their members, one to a line; a variable, a field, a constant with its value, a variant with its fields' types, a type parameter with its bounds, a loop's part with the type it is a part of. A function of a generic type's instance, or an instance of a generic function, is written as declared, `func Pair<T>.Of(a T, b T) Pair<T>`, so that a declaration is never half its instance's. The library's printing functions take `...ref any`, which the checker's own type strings now write as the library does, where they wrote `...any`. A type of a package other than the program's own is named with its package, `ref shapes.Circle`, as the checker's messages name it. The doc comment follows: the file the object is declared in is parsed again with its comments, by `parser.ParseComments`, which `snello doc` reads them with, and the comment group the parser gives the node that declares the name is the doc; a field, a variant or a constant with none shows its line comment. Only the declaring file is parsed again, and only on a hover, so that a check as the developer types keeps no comment and costs what it did. The text is Markdown, the declaration in a `snello` block and every mark of Markdown in the comment escaped but in a line indented as code, when the editor lists Markdown in `hover.contentFormat`, and plain text otherwise. A request whose answer panics, on a check's half-typed results, is answered with the protocol's internal error, as a check that panics reports on its package.

`snello parse` prints the comments it reads the same way, a node's doc comment as its `Doc` and its line comment as its `Comment`, and its attributes as `Attrs`, on the node they belong to.

## 8. Symbols, references and rename

**The outline of a document**, `textDocument/documentSymbol`, is read from its syntax alone, its text as the editor holds it parsed again, so that it needs no check and shows what a file that does not check yet declares. A struct, an enum, a trait, a type, a function, a variable and a constant are the protocol's Struct, Enum, Interface, Class, Function, Variable and Constant; a struct's fields, an enum's variants and a trait's fields and methods are under it, and so are the methods and the functions of a type the file declares, after its members; a method of a type another file declares is named with its type, `Rect.Area`. A declaration's stretch runs from its first token to its last: the syntax tree records where a node begins and not always where it ends, so the server scans the text, and a declaration ends where its last token before the next declaration ends, a member where its last before the next member, or before the declaration's closing brace, ends; a comment is no token, so the doc comment of the next declaration is never part of the one before it. An editor that shows no tree, which says so at the handshake, gets the same symbols as a list, each member with its type's name.

**The symbols of the workspace**, `workspace/symbol`, are the outlines of every file of the workspace: every package of the module of each open document and of each folder the editor names at the handshake, the module the folder is in and every module under it, looked for again at each request, `importer.Modules`, and the package of an open document in no module. A module's packages are the importer's, `importer.Packages`: every directory under the root with a file a build for some platform chooses, but a hidden one, one under `_`, a `testdata` one and a module nested in it; and a package's files are every platform's, its tests among them, `importer.PackageFiles`. A file's outline is kept between searches and read again only when the open document's version, or the file's time and size, changed. A symbol matches when its name holds the query's letters in order, whatever their case; the name that is the query comes first, then one that begins with it, then one that holds it, then the shortest. Every match is answered, the editor showing what fits: `BenchmarkWorkspaceSymbol`, a module of 9,600 functions searched for one letter, which every one matches, answers in 16 ms with 2.4 MB, which asks for no limit, so none is set; one comes only with a measurement that asks for it. Each symbol names its package, or the type it is a member of. The outline of a document never saved, `untitled:`, is read from the editor's text.

**References**, `textDocument/references`, are every name that declares or uses the object under the cursor, `types.Info.Defs` and `Uses`. Each check makes objects of its own, so an object is known across checks by where it is declared: its file and the offset of its name. A name no other package can name, one not exported, `ast.IsExported`, is looked for in its own package; any other in its package and in every package of the workspace's modules that imports it, directly or through another, each import resolved through its module as the importer resolves it, `Module.Lookup`, so that a module required as a directory, inside the module or beside it, is followed; a name declared outside the workspace, by the standard library or a module required by version, in every package of the workspace. Of those, only a package with a file, of any platform, that has the name among its tokens is checked, since no other can use it, or, for a rename, the new name, since a package that spells it alone is one whose meaning the rename may change; and each is checked, when the request is answered, as `checkAll` checks a package, for the host and for each other platform its files differ for, so that `use_linux.snello` and `use_windows.snello` are searched on a Mac. A method called through a trait bound is the trait's method, as for definition, so the references to a trait's method include those calls; a type's own method that implements it is an object of its own. From the copy of a standard file a definition opened, the references are the workspace's, and the declaration, asked for, is the copy's.

**Rename**, `textDocument/rename`, is the references of the object, its declaration included, each replaced by the new name, every edit of a document in one list; an editor that takes documents' edits gets each with the version of its open document, so that it applies none to a document that changed since. Before it answers, rename refuses, with why:

- a name the language declares, `int`; a package's name, which is its directory's; a name the standard library declares, since the library is the compiler's; a name of a module required by version, which the module cache holds, or of a module the editor has no file or folder of. A program in no module is the editor's to rename in;
- a new name that is a keyword or not one name to the scanner;
- a rename where a package that can use the name does not check as it stands, since a file of it does not parse, so that its uses are not known; or where a name spelled as the old one has no object, as a use of a package that does not compile has none; the refusal names the file;
- a method that shares a dispatch with another of its name, a type's that implements a trait's, a trait's that overrides one of a trait it refines, is renamed with all of them, its group, in the one edit. The group is found from declarations, since a type names its traits after `impl` and a trait the traits it refines: in every package that can name the method, each type and trait that implements or refines a trait answering with a method of the group, or an instance of a generic one, `Box<int>` of `Box<T>`, `types.Named.ImplementsDecl` and `types.Trait.RefinesDecl`, joins its method of that name to it. A group with a method the editor does not edit, a method of a trait the language declares, `Clone.Clone`, or of a required module, is refused, naming it, since renaming the rest would part them from it; the packages that can name each method of the group are searched, so that a trait's method in one package and a type's in another are renamed together. After the rename, under the new name, the group must share its dispatch with nothing it did not: a method renamed onto a name another dispatch uses, a type's `Explain` to its trait's default `Describe`, would override the default where it did not, and is refused, naming the method;
- edits after which the checker reports an error the checks before them did not: the searched packages are checked again for each platform with the renamed text in place of their files, and the errors compared, by file and message, an error of before matching one after either as it was or with the old name, as a word, written as the new one, and the lines and columns a message holds left out, since the edits move them; a new one refuses the rename with the checker's message and where: `Area redeclared in this block`, for a function renamed to a name declared beside it, or a name no longer exported where another package uses it;
- edits after which a name refers to another declaration than it did: every renamed name must refer to the renamed object, and every name spelled as the new name before must refer to what it did, each at its place moved by the edits before it in its file. A local renamed to the name of one of an enclosing scope that it then hides, `x` to `y` in `y := 10; { x := 2; fmt.Println(x + y) }`, compiles and prints another number; it is refused.

`textDocument/prepareRename`, for an editor that asks before it offers the name to change, answers the name and its stretch, or the refusals of the first two kinds.

Where Snello's rename goes beyond the precedents: it renames a method with the whole of its dispatch from any member of it, where Go's server, whose interfaces are satisfied implicitly, must begin from the interface and has had renames miss implementations; and it refuses every rename after which the program would compile and do something else, a name captured by another scope, a method that would override or stop overriding, where the precedents refuse the ones that would not compile.

## 9. Completion

`textDocument/completion` answers in four places, decided by the token at the cursor: after a dot, on a name or where one may begin, in an import's path, and with nothing in a string, a char literal or a comment, on a number, or at a name the check does not look up, a declaration's. An empty answer is an empty list, which the protocol asks for in place of none.

**One check, at the place typed.** The name being typed, the letters around the cursor or none, is written over by a name of the server's own, `_snello_completion_`, in the text a completion checks, and the one check that holds the file is run with it, for the platform the file is built for: the program the file is, in a directory of programs of one file, the package's tests, for a test file, and the package's sources otherwise. A name parses wherever a name may stand, after a dot, `r._snello_completion_`, and where a statement or an expression begins, `x := _snello_completion_`; and a line typed half way, `if r` with no block yet or `print(r` with no closing parenthesis, does not parse, so the check takes the parser's recovery of the file, `importer.Options.Recovered`, which keeps the name in the tree, and checks it: a load that asks for it checks a package with a file that does not parse, reporting the parse's errors, and only a completion asks, since what it reads of the check is the names. The checker meets there what no parsed file holds, an if or a loop without its block, a match arm without its body, a char or an import's path without its closing quote: it passes each over, since the parser reported it, and `TestRecoveredNoPanic` checks every example and every feature program cut part way and with a stretch taken out, at sixteen places each, and holds the check to no panic. The loader is told the place, `importer.Options.At`, a file and an offset, which it makes a position once the file is parsed; the checker, `types.Config.At`, records in `types.Info.Visible` the objects visible there when it resolves the name at that position, in whatever scope it is: a block's, a condition's, a match arm's, a closure's. A local declared further down is not visible, since the walk has not declared it yet when it resolves the name; nothing is recorded for any other place, and a check given no place records nothing, so that a build and a keystroke's check cost what they did. A package whose import does not compile is not checked past the import, as `snello check` stops, and answers no names until the import compiles.

**On a name.** The names visible, the innermost scope's first, each scope's by name, a name an inner scope hides left out, `types.Scope.Visible`: the locals of the blocks around the place, the function's parameters and receiver, the file's imports, the package's declarations, and the language's predeclared names; then the keywords, but `switch`, which the language reserves to refuse, `token.Kind.IsRefused`. On a name in a struct's literal, a key being typed or a value, the struct's fields come first; on a key written, `X:`, the fields alone; on a name where a type is written, `var w Mi`, the types and the packages' names alone.

**After a dot.** The members of what is before the dot, as the check types it: a package's exported names, `types.Scope.Names`, and its types alone where a type is written, `var p lib.`; a type's functions, `Point.Origin`, `lib.Point.Origin` and `lib.Box<int>.Of` alike, and a type parameter's, `T.New`, from its bounds; a value's fields and methods, through a borrow or a pointer, `types.Named.Methods` its own and those its traits' defaults give it, a type parameter's from its bounds, `types.TypeParam.Methods` and `Fields`, the methods written with `Self` among them, a trait value's, and the methods the language predeclares on its kind, a slice's `Push`, a string's `ToUpper`, an option's `Unwrap`, whose names the library's documentation of them, `std/builtin`, gives and whose signatures the checker's, `types.BuiltinMethod`. A value's list holds no function of its type, which a value does not call, and no `Drop` of a type that implements it, which runs once, on its own, and which the checker refuses a program calling; and a member another package declares unexported is left out by the checker's own rule, `types.Declarer`: the package of the type, or, for a member a trait gives, of the trait.

**In an import path,** inside an import's quotes: every package of the standard library but `builtin`, `importer.Paths`, and every package of the module, by its path under the root, `importer.Packages`, those that begin with what is typed, each written over the quoted text.

Each item has its kind and, as its detail, its declaration as hover writes it, `types.ObjectString`. The order is the one above and nothing else: each item carries its place in the list as the text an editor sorts by, so that no ranking by use or by match reorders it, and the same place answers the same list every time. No snippets.

## 10. Why the standard library is checked with every check

A session could check the standard library once, for each platform, and every check import from it: the library cannot change while the server runs. It was built: the library's files took positions of a stretch of their own, above every check's, every standard package was checked before the first check, and after each check the generic declarations of the library were taken back to the instances they held before it. A check of the 35 packages under `examples/` went from 72 ms to 14 ms and the server's peak with all of them open from 34 MB to 28 MB. A review found it unsound, and it was taken back:

- **The checker keeps what a check works out on the objects of the packages it imports.** An instance of a generic type keeps the methods it is asked for, made on first use; a type parameter keeps the methods and fields of its bounds; a trait keeps its methods as a value; a generic type and a generic trait keep their instances. An instance the library made for itself, `iter.Filter<json.Elements, json.Node>`, kept a method a check made, whose result was an instance the check made; taking the library back let that instance go and kept the method, and the next check made the same type again as another, and refused the program for it, where `snello check` did not.
- **The checker reads what the library's check recorded.** The check of reflection follows a generic function of the library into its body, `json.Marshal` into `json.writeValue`, through the names and types the check of the library recorded; the shared library had let them go, and the server missed an error of reflection `snello check` reports.

What sharing needs first is a checker that keeps nothing of a check on an imported package's objects: the instances of a generic type or trait, the methods an instance is asked for and those of a type parameter's bounds, each in the check that made them, and the records of the library's generic bodies kept with the library for the walks that follow them. Then the library can be shared, sound by construction, with the measurements above. Until then every check loads the library again, which is correct and costs what section 11 measures.

## 11. Cost and memory

The server holds the text of the open documents, the diagnostics of the last check of each package with one open, and the view that check left, trimmed to what hover and definition read. A check's view replaces the last one of its files as soon as it is kept, so that a round of checks holds one round's views, and a package with no open document left drops its own. A keystroke costs the check of the packages with open documents. `BenchmarkCheck` measures it over every package under `examples/`, each with its tests, open at once: 72 ms and 477,000 allocations for the 35 packages on an eight-core arm64 Mac, 2.0 ms and about 13,600 allocations a package. With all 42 of the examples' files open, the views hold 11 MB live, about 0.3 MB for each open package, and the server's peak, with the collector's room and a round of checks under way, is 34 MB, where it was 15 MB when the server kept nothing between checks. References and rename check, when they are asked, the packages that can use the name: `BenchmarkReferences` finds the 73 uses of a function at the bottom of a chain of ten packages of eight files of forty functions each, every package using it, in 40 ms, and checks its rename in 68 ms, the packages checked before and after the edits; the outline and the workspace's symbols read syntax alone, each file once until it changes.

## 13. What is not here

Formatting is a task of its own, and so is the editor extension, which starts `snello lsp` and gives the editor Snello's grammar. A syntax error stops its package's check, as `snello check` stops: the file with the error answers nothing until it parses, and the files beside it, unchanged since the last check that typed them, are answered from that check. The pulled diagnostics of protocol 3.17, files changed on disk outside the editor, `workspace/didChangeWatchedFiles`, and a file that exists only in the editor joining its package before it is saved are not here. A file whose name begins with a dot or an underscore is no package's, and is never checked; the module file is read from the disk, never as the editor holds it.

## Decisions

- **One checker.** The server checks through the compiler's own loader and checker, so the editor and `snello check` agree on every program, message for message, and nothing runs beside it.
- **One binary.** The server is `snello lsp`, the compiler it ships with, installed with it.
- **No settings.** A module is found by `snello.mod`, a file's platform by its name, the library is in the compiler; the server reads no configuration.
- **Every open file for its own platform**, its errors labelled with the platform when it is not the host's; references and rename search every platform's files.
- **A whole package on every change**, every package with an open document, changes that arrive during a check applied together, because one file's change can break another's and the measurement shows it is cheap.
- **The standard library checked with every check**, until the checker keeps nothing of a check on an imported package's objects: sharing it was measured and found unsound, section 10.
- **The editor's buffers through the loader's read function**, for the open file's package and every package it imports; the disk elsewhere.
- **The module from the cache alone**: nothing fetched, hashed or written as the developer types; a module the cache lacks names `snello fetch`.
- **UTF-8 positions when the editor offers them**, UTF-16 otherwise.
- **Pushed diagnostics**, on the file each error names, the union of every check's, cleared when a check no longer reports them.
- **Test files checked as `snello test` loads them**, never through the generated runner.
- **A directory of several files that declare `main` is programs of one file each**, checked alone, as they are built.
- **A position names one file of a program**, so a definition is found in any package the program reaches.
- **Hover is the checker's declaration and the parser's doc comment**, the comment read from the declaring file on the hover, never kept by a check.
- **A view keeps what its answers read**: the information on the package's own files; a file that does not parse keeps the last view of the files beside it.
- **A definition in the standard library opens a read-only copy in the cache**, answered from the library's own check and never checked as the developer's.
- **The outline from the syntax alone**, so that a file that does not check still shows what it declares.
- **An object is known across checks by where it is declared**, its file and its name's offset.
- **A method is renamed with its whole dispatch**, found from the `impl` lists and the traits refined, from any member of it; refused only when a member is not the editor's to change.
- **A rename that would compile and do something else is refused**: a new error of the checker, a name that would refer to another declaration, a method that would override or stop overriding.
- **Completion at the place typed**: the name being typed is written over by one of the server's own so that the text parses, and the checker records the names visible where it resolves that name, and nothing anywhere else; members from the checked type; the same list for the same place every time.
- **No number without a measurement**: no limit, cache or shortcut is taken from another server; each comes with the measurement that asked for it.
