# The language server

Status: being built. The server, its documents, its diagnostics, hover and definition, `snellols`; symbols, completion and formatting are later tasks of the same milestone, and the editor extension is its own.

An editor learns what a program means from a language server: a process it starts beside itself and talks to over the Language Server Protocol, JSON-RPC 2.0 messages on the server's standard input and output. This note gives Snello one, `snellols`, written in Go beside the compiler and built from the same packages, so that what the editor shows is what `snello check` says, word for word, with no second front end to drift from the first.

## The precedents

Every language with a server of note runs its own checker in it rather than a second one written for the editor: Go's `gopls` runs `go/types`, Rust's `rust-analyzer` its own front end, which the compiler is slowly converging on, clangd the compiler's front end itself. Where a server's checker differs from the compiler's, the editor shows errors the build does not, or misses ones it does, and developers learn to distrust it; the servers that kept one checker kept that trust. The same servers answer hover with the declaration as their checker types it and its doc comment, and definition with a place in a file, the standard library's included: `gopls` opens Go's in GOROOT, `rust-analyzer` Rust's in the toolchain's sources. `gopls` began, as this one does, by checking a whole package on every change and caching nothing below the package; it grew an incremental cache once packages and workspaces grew large enough for a whole check to be noticed. The protocol is one for every editor, VS Code's, Neovim's, Helix's, Emacs's and Zed's among them, so one server serves them all.

## 1. The process and the protocol

`snellols` reads messages from standard input and writes them to standard output, each a header, `Content-Length: N`, a blank line, and N bytes of JSON; a `Content-Type` header, which the protocol allows, is read and ignored. Logs go to standard error, which editors show in their output panes, never to standard output, which is the protocol's.

Three packages under `lsp/` hold it, each with its tests, as `compiler/` holds the compiler: `lsp/jsonrpc` the framing and the messages, a request with an id, a notification without, a response with a result or an error; `lsp/protocol` the protocol's types, only the ones the server uses, named as the specification names them; and `lsp/server` the server itself. `cmd/snellols` is the command: it runs the server over its standard input and output and exits with the code the protocol asks for, 0 after a `shutdown` and an `exit`, 1 after an `exit` alone or a closed input.

A request is answered once, in the order its work finishes, which for this server is the order it came in. A request the server does not know is answered with the protocol's `MethodNotFound`; one before `initialize` with `ServerNotInitialized`; a notification the server does not know, and every `$/` notification, `$/cancelRequest` included, is passed over, as the protocol allows, since nothing here runs long enough to be worth cancelling.

## 2. What the server says it does

`initialize` is answered with the capabilities of what is built and no more, so that an editor never asks for what the server cannot give:

- `textDocumentSync`: open and close, incremental changes, and saves without their text;
- `positionEncoding`: UTF-8 when the editor offers it, UTF-16 otherwise (section 5);
- `hoverProvider` and `definitionProvider` (section 7);
- `serverInfo`: `snellols` and the compiler's version.

The diagnostics are pushed, `textDocument/publishDiagnostics`, which every editor takes; the pulled form of protocol 3.17 asks the editor to poll, and adds nothing a push does not give a server whose checks are this quick.

## 3. Documents

The server keeps the text of every document the editor has open, by its URI, with the version the editor gave it. `didOpen` stores it; `didChange` applies each change in turn, a range replaced by its text or, with no range, the whole text replaced; `didSave` changes nothing, since the editor's text is already the file's; `didClose` forgets the document, and the next check reads the file from disk. A change is applied to the bytes the server holds, its range converted from the editor's positions to byte offsets in the text as it stands before that change, as the protocol orders the changes of one notification.

A package is checked from these buffers where a file of it is open and from the disk elsewhere: the loader reads every source through a function the server gives it, `importer.Options.Read`, `Load.Read` and `Importer.Read`, which answers from the open documents first. Each reads through `os.ReadFile` when no function is given, as every command of the compiler does. The read reaches the packages the open file's package imports too, so a library package edited in one window and imported in another is checked as it stands in the editor. A file that exists only in the editor, created and not yet saved, joins its package when it is saved, since the package's files are listed from the directory: a save is checked as a change is, which also picks up a file of an imported package saved from another editor.

The module's requirements are resolved from the module cache and the lock file alone, `Module.ResolveCached` through `importer.Options.Cached`, never as a build resolves them: a build fetches a module the cache lacks, fetches again a copy whose files changed, hashes every module, writes `snello.lock`, and removes it when nothing is required by version. A check as the developer types does none of it: it would reach the network, and write the program's files, on every keystroke. A required module the cache does not hold is an error naming `snello fetch`, which puts it there; a cached copy is held to the lock file's record, and its files are not hashed, which the build does.

## 4. Checking

A document's package is its directory's, checked as `snello check DIR` checks it, through the one function both use, `importer.CheckDir`: as a program when its package is `main` or the directory is a module's root, as a library under the module's rules otherwise. The package's test files are then checked as `snello test` loads them: the test runner's plan, `testrun.PlanDirFrom`, says whether they are a main package's, the package's own or an external test package's, `NAME_test`; a main package is checked with its test files, and a library by the import path its tests are reached at, `importer.CheckTests`, so that every error keeps the test file and the position it names. The runner `snello test` generates is not checked: an error there would name a file the developer never sees.

A directory in which more than one file declares `main` holds programs of one file each, as `examples/tree/` holds two, each built by `snello build FILE`; the server checks each such file alone, as `snello check FILE` does, where `snello check DIR` would report the second `main` as a redeclaration. The rule follows how the programs are built, and no file of a package of several files declares `main` but one.

Every package with an open document is checked again after every change, whole, from its files to its imports, the standard library's included: about 2 ms a package for the packages under `examples/`, tests included, on an eight-core arm64 Mac (section 9), so a keystroke's check is done long before the next. Changes that arrive while a check runs are applied together, and every package with an open document is checked once after them, so a burst of typing costs one check at its end, never one per key behind the keys. The server reads messages on one goroutine and does everything else on another, which owns the documents and the results, so that nothing it keeps is shared between them.

## 5. Positions

The compiler's position is a line and a column in bytes, both from 1. The protocol's is a line from 0 and a character in the units the editor and the server agreed: UTF-16 code units by default, the units of JavaScript's strings, or UTF-8 bytes, or code points, when the editor offers them in `general.positionEncodings` (protocol 3.17). The server takes UTF-8 when offered, since it is the compiler's own unit and needs no conversion, and UTF-16 otherwise, which every editor understands. A column in UTF-16 is counted over the line's text up to the byte: a character of the Basic Multilingual Plane is one unit, one beyond it, an emoji, two. A tab is one unit, as the protocol counts it.

## 6. Diagnostics

Every error the parser or the checker reports becomes a diagnostic of severity Error, with source `snello` and the compiler's message, on the file the error names. Its range starts at the error's position, its byte offset converted to the protocol's line and character, and covers the word there, an identifier, a keyword or a number, or the one character there when it starts none, since an editor underlines a range; at a line's end or the text's end it is a point, which an editor marks at the end of the line. The parser stops a check: a file that does not parse reports its syntax errors alone, and the checker's appear once it parses, as `snello check` reports them.

An error without a position, a module file that does not parse or a package of no files, is reported on the first line of every open document of the package, so that it is seen where the developer is; one of the tests' alone, on the open test files. A package that imports one that does not compile reports it as the checker does, on the import, with the imported package's errors in its message; the imported package's own file shows its errors once it is open, since its own check then names them. The loader keeps such a package's errors whole behind the message, so that a check of the package itself finds each one's file and position. A file's diagnostics are the union of what every check reports on it. A check that reports nothing on a file it reported on before publishes an empty list for it, which clears the editor's marks; closing a document publishes its file's diagnostics again from the remaining checks, and nothing for a file no check names.

## 7. Hover and definition

Both start from the place under the cursor in what the file's last check left, its view. A check is handed every file it parses, the program's and every package's it imports, through `importer.Options.Parsed`, as each is parsed, a file with errors too; once the check ends, its view keeps the checker's `types.Info` on the names and expressions of the package's own files and those files' syntax, every file it parsed, which a position is resolved against, the sources it read, and the type each function of a type belongs to, and lets the rest go: what the check knew of its imports' insides no request reads. A package's files are answered from the check of its sources, its test files from the check of its tests. A request about a document waits for the check of the changes that came before it in the same batch of messages, so that it is answered on the latest text.

The place holds the identifier whose letters cover the cursor, or that ends there, where a cursor after a word stands, found by `ast.Inspect`; `types.Info.Defs` or `Uses` gives the object it declares or uses. With no identifier there, the token there, scanned from the text, belongs to the innermost node that records it as its own: the operator of a binary expression, the parenthesis of a call, a literal. Its type, from `types.Info.Types`, is the hover; a place with neither has none.

**Definition** is the object's position, resolved to its file. A load parses every file into one `token.FileSet`, the program's and every package's it imports, so that a position names one file of the whole program, as one `go/token` set does for a Go program; a set of each package's own, as the loader had, gave two packages the same positions. A position a file does not hold resolves to no line, where it was read against the wrong file's lines. A method called through a trait bound is the method of the trait, which is what the checker gives the type parameter, so the definition lands on the trait's declaration. A name the language declares, `int` or `len`, has no definition. A name of the standard library is declared in a file the compiler holds and the disk does not: the server writes the file to `std/VERSION/PATH` in Snello's cache directory, the one `SNELLO_CACHE` names or `snello/` in the user's cache, once for each version of the compiler and again when its text differs, through a file renamed into place so that no reader finds it half written, and points the editor there. The copy is read-only, since an edit to it changes nothing, and its name must be a path under `std/`. An editor that opens it checks nothing: a document under the copies of this version is the library's package, answered from a check of the package in the compiler, with its privileges, and reports no diagnostic, and a copy of another version's is neither checked nor answered. With the cache off, the request is answered with an error that says so. The range of a definition is the token there, the whole path of an import for a package's name.

**Hover** is the declaration as the checker types it, `types.ObjectString`: a function with its type parameters' bounds and its parameters' names, `func Largest<A: Shape, B: Shape>(a ref A, b ref B) f64`; a method with its receiver; a function of a type with its type, `func Point.Origin() Point`, which the server reads from the declaration, since the function's object does not keep it and keeping it would grow every function object by a word; a struct, an enum and a trait with the traits after `impl` or the colon and their members, one to a line; a variable, a field, a constant with its value, a variant with its fields' types, a type parameter with its bounds, a loop's part with the type it is a part of. A function of a generic type's instance, or an instance of a generic function, is written as declared, `func Pair<T>.Of(a T, b T) Pair<T>`, so that a declaration is never half its instance's. The library's printing functions take `...ref any`, which the checker's own type strings now write as the library does, where they wrote `...any`. A type of a package other than the program's own is named with its package, `ref shapes.Circle`, as the checker's messages name it. The doc comment follows: the file the object is declared in is parsed again with its comments, by `parser.ParseComments`, which `snello doc` reads them with, and the comment group the parser gives the node that declares the name is the doc; a field, a variant or a constant with none shows its line comment. Only the declaring file is parsed again, and only on a hover, so that a check as the developer types keeps no comment and costs what it did. The text is Markdown, the declaration in a `snello` block and every mark of Markdown in the comment escaped but in a line indented as code, when the editor lists Markdown in `hover.contentFormat`, and plain text otherwise. A request whose answer panics, on a check's half-typed results, is answered with the protocol's internal error, as a check that panics reports on its package.

`snello parse` prints the comments it reads the same way, a node's doc comment as its `Doc` and its line comment as its `Comment`, and its attributes as `Attrs`, on the node they belong to.

## 8. What is not incremental

Nothing below the package is kept between checks: every check parses and checks every file of the package and of every package it imports. It is the simplest form that is right, and fast enough for the packages Snello has. What would change for a workspace large enough to notice: a cache of the checked packages by their import path and the hash of their sources, the standard library's first since it never changes under the editor; a package checked again only when one of its files, or of the packages it imports, changed; and, last, a parse of the edited file alone, reusing its siblings' syntax. Each waits for a measurement that asks for it.

## 9. Cost and memory

The server holds the text of the open documents, the diagnostics of the last check of each package with one open, and the view that check left, trimmed to what hover and definition read. A check's view replaces the last one of its files as soon as it is kept, so that a round of checks holds one round's views, and a package with no open document left drops its own. A keystroke costs the check of the packages with open documents. `BenchmarkCheck` measures it over every package under `examples/`, each with its tests, open at once: 72 ms and 476,000 allocations for the 35 packages on an eight-core arm64 Mac, 2.0 ms and about 13,600 allocations a package; one set of positions for a load, in place of one for each package, took 11,000 allocations off the 483,000 of a set for each, and trimming the views costs back 0.1 ms a package. With all 42 of the examples' files open, the views hold 11 MB live, about 0.3 MB for each open package: the type objects the package's names reach, the kept information on its own names, its files' syntax, the line tables of the files the check parsed, and the text of the library's files, which the names of its declarations are read from. The server's peak, with the collector's room over that and a round of checks under way, is 34 MB, where it was 15 MB when the server kept nothing between checks.

## 10. How it is tested

`go test ./lsp/...`. The framing is tested on a message split across reads, two messages in one read, a header with a content type, and a header that is not the protocol's. The positions are tested on ASCII, a two-byte character, a four-byte one, a tab and a line past the end, in both encodings. The documents are tested on a change at the start, the middle and the end of a line, across lines, after a non-ASCII character, and a whole replacement. The server is tested over a pipe in a scripted session: it is initialized, opens a file of a module, has it edited into a syntax error, a type error and back, and reads the diagnostics each time; an error in another file of the package is reported on that file; an unsaved buffer is checked as it stands; a file not open is read from disk; and every package under `examples/`, its tests included, opens with no diagnostic, the two programs of `examples/tree/` each checked alone, while the pending `cli-grep` shows the errors `snello check` prints, message for message. Definition and hover are tested in sessions over `examples/packaged/`: a definition in the file, in another file of the package, in the program's own package `shapes`, from a test file, on a package's name, through a trait bound to the trait's method, and in `fmt`, whose copy is written to a cache of the test's own and written again when it differs, and refused with the cache off; a hover on a function, a method, a struct, a trait, an enum, a variant, a variable, a package variable, a constant of `math`, a field, a test file's type, an operator and a literal, each declaration with its doc comment, in Markdown and in plain text; a hover sent right after a change, answered on the changed text; a copy of the library opened, answered from the library and with no diagnostic, and another version's copy answered with nothing; a syntax error typed into one file, which darkens that file alone; and a request whose answer panics, answered with the internal error. The lookups under them, the identifier at a place, the token, the node that owns it, the node that declares a name, the escaping of Markdown and the copies' paths, are tested on their own. The loader's read function, its `Parsed` callback with the positions of one load apart, `importer.CheckDir` and `importer.CheckTests` are tested in the importer's package, the plan read through a function in the test runner's, `types.ObjectString` on every kind of declaration in the checker's, and `snello parse` on the comment groups of every example.

## 11. What is not here

Symbols, references and rename (#115), completion (#116) and formatting (#118) are later tasks, each a capability the server will then announce. A syntax error stops its package's check, as `snello check` stops: the file with the error answers nothing until it parses, and the files beside it, unchanged since the last check that typed them, are answered from that check. The editor extension, which starts `snellols` and gives the editor Snello's grammar, is #117. The pulled diagnostics of protocol 3.17, files changed on disk outside the editor, `workspace/didChangeWatchedFiles`, and a file that exists only in the editor joining its package before it is saved are not here either. Three kinds of file are never checked: one named for another platform, `poll_windows.snello` on macOS, and one whose name begins with a dot or an underscore, which no package of this machine holds; and the module file as the editor holds it, since the module is read from the disk.

## Decisions

- **One checker.** The server checks through the compiler's own loader and checker, so the editor and `snello check` agree on every program, message for message.
- **A whole package on every change**, every package with an open document, changes that arrive during a check applied together; nothing is cached below the package until a measurement asks for it.
- **The editor's buffers through the loader's read function**, for the open file's package and every package it imports; the disk elsewhere.
- **The module from the cache alone**: nothing fetched, hashed or written as the developer types; a module the cache lacks names `snello fetch`.
- **UTF-8 positions when the editor offers them**, UTF-16 otherwise.
- **Pushed diagnostics**, on the file each error names, the union of every check's, cleared when a check no longer reports them.
- **Test files checked as `snello test` loads them**, by the test runner's plan and the importer, never through the generated runner.
- **A directory of several files that declare `main` is programs of one file each**, checked alone, as they are built.
- **A position names one file of a program**: one `token.FileSet` for a load, so a definition is found in any package the program reaches.
- **Hover is the checker's declaration and the parser's doc comment**, the comment read from the declaring file on the hover, never kept by a check.
- **A view keeps what its answers read**: the information on the package's own files, not its imports' insides; a file that does not parse keeps the last view of the files beside it.
- **A copy of the library is the library's package**, answered from the compiler's own and never checked as the developer's.
- **A definition in the standard library opens a copy in the cache**, written once for each version of the compiler, since the library is in the compiler and not on the disk.
