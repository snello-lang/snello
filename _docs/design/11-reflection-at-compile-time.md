# Reflection at compile time

Status: designed.

Reflection is a function looking at the type it was given: which kind of type it is, a struct's fields by name, an enum's variants. With it, one function serves every type: an encoder for JSON, a printer for debugging, a diff of two values for a failed test, a parser of command-line flags into a struct, a loader of a configuration file. Without it, each of those is written again for every type, or generated by a tool.

In Snello all of it happens while the program is compiled. A generic function asks about its type parameter with `match T`, goes through a struct's fields with `for f := range fields(T)`, reaches a field with `v.[f]`, and builds a value from its fields. The compiler checks the function once, as it checks any generic function. When it compiles the function for a type, it keeps the one arm that type matches and writes the loop out once per field, each field's name a constant. What runs is the code a programmer would have written by hand for that type: no description of a type is kept in the program, nothing is looked up by a type's name, nothing goes through a table.

Package `encoding/json` in the standard library is written this way, and shows how any such library is.

## An example

Encoding, for any type the arms cover:

```go
func writeValue<T>(v ref T, out mut strings.Builder) {
    match T {
        bool => out.WriteString(if v { "true" } else { "false" })
        i8 | i16 | i32 | i64 | int => out.WriteString(strconv.Itoa(int(v)))
        f64 => out.WriteString(strconv.FormatFloat(v, 'g', -1, 64))
        string => writeQuoted(ref v, mut out)
        E? => match v { Some(x) => write(x, mut out), None => out.WriteString("null") }
        []E => {
            out.WriteByte('[')
            for i, e := range v {
                if i > 0 { out.WriteByte(',') }
                write(e, mut out)
            }
            out.WriteByte(']')
        }
        struct => {
            out.WriteByte('{')
            first := true
            for f := range fields(T) {              // written out once per field
                if !first { out.WriteByte(',') }
                first = false
                writeQuoted(ref f.name, mut out)               // a constant string
                out.WriteByte(':')
                writeValue(ref v.[f], mut out)            // the field, lent
            }
            out.WriteByte('}')
        }
        enum => match v {
            for c := range variants(T) => {         // one arm per variant: v holds c in it
                out.WriteString("{")
                writeQuoted(ref c.name, mut out)
                out.WriteString(":{")
                ...                                  // fields(c), as a struct's
                out.WriteString("}}")
            }
        }
    }
}
```

For `struct Point { X int; Y int }`, `writeValue<Point>` is compiled as if it read:

```go
out.WriteByte('{')
writeQuoted(ref "X", mut out); out.WriteByte(':'); writeValue<int>(ref v.X, mut out)
out.WriteByte(',')
writeQuoted(ref "Y", mut out); out.WriteByte(':'); writeValue<int>(ref v.Y, mut out)
out.WriteByte('}')
```

and `writeValue<int>` as the one line of its arm.

Decoding builds the value from its fields, each found in the input by its name, of the field's own type:

```go
func readValue<T>(r mut reader) Result<T, Error> {
    match T {
        ...
        struct => {
            var o objectState                            // where each key's value lies, once a key comes out of order
            return Ok(T{ for f := range fields(T) {
                [f]: if r.seekField(mut o, f.name)? { readValue<f.type>(mut r)? }
                     else { f.default ?? return Err(missingFieldError(r.at, f.name)) }
            } })
        }
    }
}
```

## The precedents

- **Go** reflects when the program runs: `reflect` reads a description of a value's type, kept in the binary for it, and `encoding/json` walks it for every value, which is why generators such as `easyjson` exist, to write the code per type the walk replaced. Struct tags rename a field, strings the compiler does not check.
- **Rust** keeps nothing at run time; `serde`'s derive macro writes code per type that hands each field to a serializer trait. Reflection is not in the language: it is a macro outside the type checker.
- **Swift** has `Mirror`, which reads a value's children when the program runs, and `Codable`, written by the compiler for a type that lists it.
- **Zig** gives a type's description at compile time, `@typeInfo(T)`, and an `inline for` over its fields that the compiler unrolls per type, which is what Snello does. Zig gets it by running any code in the compiler, `comptime`, a second language with its own rules; Snello gives the few things reflection needs and runs nothing in the compiler.
- **C++** checks a template for each type it is used with, so its mistakes appear at the use; Snello checks a reflecting function once, and only the questions a type can answer, which arm it takes and which fields it shows, are asked where it is used.

## 1. `match T`: which type

A `match` on a type parameter of the function, or of its receiver's type, chooses an arm by the type:

| Arm | Matches | In the arm |
|---|---|---|
| `int`, `string`, `f64` | that type alone | `T` is read as the arm's type |
| `i8 \| i16 \| i32` | any of them | the arm is checked once for each |
| `Point`, `List<int>` | that declared type | `T` is read as it |
| `E?`, `[]E`, `*E` | an option, a slice, an owned pointer | `E` is a type parameter of the arm's |
| `map[K]V` | a map | `K` and `V`, `K` with `Eq` and `Hash` |
| `struct`, `enum` | any struct, any enum | `T`'s fields or variants are reached |
| `json.Marshaler`, a trait | any type that implements it | `T` is bounded by the trait: its methods and functions are called |
| `_` | any other type | |

- **Arms are tried in order**, the first that fits taken: `Point` before `struct` handles `Point` its own way.
- **An arm may name a trait.** It takes any type that implements the trait, and in it `T` is bounded by the trait as a `T: json.Marshaler` would be, so `v.MarshalJSON(...)` and `T.UnmarshalJSON(...)`, a function of the type (`00-syntax-conventions.md`, Functions of a type), are called on it; each instance calls the type's own. A library puts it first, so a type with its own encoding is written its own way and every other by its fields. A generic trait is not named in an arm in this version, with its arguments, `Conv<int>`, or binding them, `Iterator<E>`: `an arm names a trait without type arguments in this version`. A match inside the arm is on `T` so bounded, and its `struct` or `enum` arm reaches the parts as any does, the trait's methods still callable.
- **An arm's name names something.** A whole arm that is a name nothing declares, `Shw`, would bind any type as a shape's name does and take every type the arms after it are for, so it is refused: `Shw names no type or trait: an arm for any type is _`.
- **An arm naming a type takes that type alone.** A type declared over another, `type Celsius f64`, is a type of its own, as it is to assignment, and takes an arm that names it, its kind's, `struct` for a type declared over a struct, or `_`, never the `f64` arm: a `Celsius` written as an `f64` would lose what its name says, and an arm that wants every type declared over `f64` would have no way to name them. Go's type switch matches a declared type by its name alone, as here.
- **An arm reads `T` as what it matched.** `v` of type `ref T` in an `int` arm is a `ref int`, and in a `[]E` arm a `ref []E` whose elements are `E`. A shape's names, `E`, `K`, `V`, are type parameters of the arm, and a `match` on one of them is a match on a type as `match T` is.
- **It is not exhaustive by itself.** A type no arm matches is refused where the function is used with it (section 4); an arm `_` takes every type the others do not.
- **An arm takes no guard**, since a type is matched by what it is. A `match T` is a statement or an expression, as `match` is; as an expression, its arms give one type.
- **Not in this version:** an arm for an array's length or a tuple's elements. An array or a tuple is matched by its type, `[4]byte`, or by `_`.

## 2. Fields and variants

In a `struct` arm, `fields(T)` gives the struct's fields to a `for` loop, which the compiler writes out once for each:

- **`f.name`** is the field's name as declared, a constant string. **`f.type`** is its type, written where a type is, `readValue<f.type>(...)`, and matched with `match f.type`. **`f.default`** is its default (`00-syntax-conventions.md`, Default field values), an `f.type?`, `None` for a field that declares none.
- **`v.[f]`** is the field `f` of `v`, as `v.x` is the field `x`. It is lent: read through a `ref`, changed through a `mut`, never moved out of `v`, since the function cannot know whether `T` implements `Drop` (`00-syntax-conventions.md`, Destructors), and a field moved out of such a value would be read by its `Drop`. Its type is `f.type`, a type parameter of the loop with no bounds.
- **A value is built from its fields** by a literal with one loop in it, `T{ for f := range fields(T) { [f]: value } }`, which names every field, each given its line's value in the order of the fields; a `?` that leaves drops the fields made before it, as in any literal.
- **The loop holds no `break`, `continue`, `defer` or `select`.** It is written out once per field, and each copy is a block of its own.

In an `enum` arm, a `match` on `v` takes one arm written out once for each variant, so that it covers them all:

```go
match v {
    for c := range variants(T) => { ... }   // v holds the variant c here
}
```

- **`c.name`** is the variant's name, a constant string; `fields(c)` its fields, as a struct's, with `v.[f]` each field of the variant `v` holds.
- **The arm holds `v`.** Its fields are read as those of the variant `c`, so while the arm runs `v` is not assigned, moved or lent `mut`, `cannot assign to v: the arm written for each variant holds it`, as a pattern binding a variant's fields holds the value it matched.
- **A variant is built** by its constructor with one loop for its arguments, `c(for f := range fields(c) { value })`. Which variant to build from an input is found by its name: `for c := range variants(T) { if name == c.name { return Ok(c(...)) } }`, the loop written out once per variant.

## 3. What reflection reaches

Reflection reaches what code written by hand could, and a type opens itself to more by saying so:

- **A function reaches the fields its package can name**: every field of a type of its own package, the exported fields of another's. A struct of another package with a field the function cannot name is refused where the function is used with it, naming the field: `json.Marshal<Config>, json.writeValue<Config>: field port of Config is not exported; export it, or list Reflect on Config`. Nothing is passed over in silence.
- **`Reflect` opens a type to every package.** A type that lists the predeclared marker trait `Reflect`, `struct Config impl Reflect { port int }`, has all its fields reached by any reflecting function, and may be built by one: its package says so where it declares the type. A type that does not list it keeps what it keeps, so an `rc.Rc`, an `os.File` or a `sync.Mutex`, none of which lists it, is never read or forged by reflection.
- **`Reflect` opens what its package declares.** A type declared over another package's struct, `type Mine strings.Builder`, is a type of the program's, but the fields are `strings`'s: listing `Reflect` on `Mine` opens none of them, `field buf of Mine is not exported by strings, which declares it`, since a package cannot open what another keeps.
- **A variant** is reached by the same rule as a field: an enum of another package with a variant the function cannot name is refused unless the enum lists `Reflect`. A variant's fields are reached where the variant is, by their place, as a pattern of another package binds them whatever their names.
- **A type that holds a borrow** is refused where the function is used with it: a match on a type takes none, `a match on T takes no type that holds a borrow: Decoder does`, since an arm reads the parameter as the type it matched and could make a borrow of it the caller does not follow; and a loop over parts reaches no field that holds one, `field src of Decoder holds a borrow, ref string`.

## 4. Where the questions a type answers are asked

A reflecting function is checked once. What depends on the type it is used with is asked by the checker, after the package's functions are checked, for each type a reflecting function is used with, directly or through another generic function: from every call with types known, it follows the calls of generic functions inside, with the types each is given, through the arms each type takes and the fields each loop gives. Each question is asked once per function and type, and a mistake is reported once, at the call the program wrote, with the chain that led there:

- **No arm matches.** `json.Marshal<Server>, json.writeValue<Server>, json.writeValue<chan int>: no arm of the match on T takes chan int`.
- **A `refuse` is reached.** The predeclared `refuse(msg)` refuses the program where an instance reaches it, with the chain and its message, which is text the compiler knows, string constants and parts' names joined with `+`: `json.Marshal<Shape>, json.writeValue<Shape>, json.checkLayout<Shape>: json.Tag writes a variant's fields beside its name, and Pair has an unnamed one: name it, or add json.Content`. It says why in the library's words, where a missing arm says only which type no arm takes, as C++'s `static_assert` and Rust's `compile_error!` let a library say. For it to refuse one type and not another, the walk decides more than the arm a type takes: a match on `attr(x, A)`, whose arm `Some` is taken when `A` is written on `x` and `None` when it is not, and a match on a part's name, `c.name` or `f.name`, against string literals, for each copy of the loop it is in. A match with a guard, or on anything else, is decided when the program runs, and every arm of it is walked. Outside a generic function a `refuse` is reached by every program that holds it, and the checker reports it where it is written. It is no value, as `panic` is, and both backends write it as one, on a path no instance takes.
- **A field or variant is not reached** (section 3), or holds a borrow.
- **The types grow without end.** A function given a type that holds the type an earlier call of it on the chain was given, which holds the type a call before that was given, so that the types have grown twice through its arms, is refused: `f<int>, f<[]int>: f<[][]int> holds f<[]int>, which holds f<int>; the types grow without end`. A recursive type, an enum `Value` holding `[]Value`, does not grow: `write<Value>` asks for `write<[]Value>`, which asks for `write<Value>`, already asked for.
- **The calls go deeper than the checker follows.** A chain of more than 256 calls of generic functions, each with types not asked about before, is refused at the call it began from, naming its ends, `f0<string>, ..., f255<string>, f256<string>: the calls of generic functions go deeper than 256, more than the compiler follows`, so that every instance a backend compiles has been asked about.

The backends ask the same questions of the same function in `compiler/types`, so the arm a type takes and the fields a loop gives are decided in one place, and the program that checked is the program that is compiled. `snello check` reports all of it.

## 5. Memory safe, no collector

Reflection adds no kind of value and nothing to the program when it runs. A reflecting function is a generic function: checked once against the rules every function is checked against, then compiled per type with its loops written out, so what runs is ordinary code over ordinary values, each owned once and dropped once.

- **A field is lent, never moved** (section 2), so a `Drop` never reads a field reflection took.
- **A value is built by a literal naming every field**, so no zero is made of a type without one and no value is half made; a `?` drops the fields made before it.
- **Nothing is forged.** A type is built from its fields only where a literal of it could be written, or where its package listed `Reflect`.
- **No borrow is stored.** A field holding a borrow is refused where it would become a type argument.
- **No description of a type at run time.** The names are constant strings in the code written per type, read only by it.

## 6. `encoding/json`

Package `encoding/json` is written over reflection, with nothing per type: `Marshal<T>(v ref T) Result<string, Error>`, which refuses only a float JSON has no text for, a NaN or an infinity, as Go's does, and `Unmarshal<T>(text ref string) Result<T, Error>`, with `Error` saying what could not be read and at which offset. A struct is an object of its fields; an option `null` or its value; a slice an array; a map with string or integer keys an object, its keys sorted, an integer key written as its decimal in quotes, as Go writes one, and integer keys in the order of their values (below); an enum's variant without fields its name, `"Null"`, one with one unnamed field an object of one key holding the value, `{"Bool":true}`, one with several an array, `{"Pair":[1,2]}`, and one with named fields an object of them, `{"Circle":{"r":1.5}}`, as `serde`'s default is. Decoding finds each field by its key, wherever the input puts it, and passes over a key the type has no field for, as Go's does; a field missing from the input is an error at the object it is missing from, unless it is an option, `None`, or declares a default, which it takes; a number its field's type cannot hold is an error, `300 overflows its field`; a key given twice is an error, as Go's `encoding/json/v2` makes it.

- **The text is held to JSON's grammar**, as Go's and `serde_json`'s readers hold it: a member without its comma, a number JSON does not write, `01`, `+1`, `.5`, `1.`, a raw control character or a broken `\u` escape in a string, and text after the value are errors with their offset. A `\u` half of a pair without its other is U+FFFD, as Go reads it.
- **Nesting is bounded at 128**, `serde_json`'s limit, in a value read and in one passed over: a task's stack does not grow, and each level the reader goes into takes a frame of it, so a text of ten thousand `[` is an error, `exceeded max depth`, not a crash. Go's reader nests to 10000 on a stack that grows.
- **A float is written as Go's `encoding/json` writes it**: its shortest text, in plain decimals from `1e-6` up to `1e21` and with an exponent outside, `1e-7`, `1e+21`; an `f32` by its own shortest text, `0.1`, not the `f64`'s.
- **A string is written as it is**, with `"`, `\`, the control characters escaped and a byte of invalid UTF-8 written `\ufffd`, as Go writes it. Nothing is escaped for HTML, as `serde_json` writes it: Go's escapes `<`, `>` and `&` by default, for a text pasted into a page, which a library for data has no reason to assume.
- **A type with its own JSON.** A type that lists `json.Marshaler` is written by its `MarshalJSON`, whose text `Marshal` checks is one JSON value, as Go's does; one that lists `json.Unmarshaler` is read by `UnmarshalJSON`, a function of the type (`00-syntax-conventions.md`, Functions of a type), given the raw text of its value, so a type with no zero value decodes itself, which Go's method on a zero value cannot do; an offset in its error counts from where the value began. Both arms come first in json's match on `T`.
- **An owned pointer, `*E`,** is the value it points at, and reading one allocates it, so a recursive struct through a pointer, `struct Node { V int; Up *Node? }`, round-trips.
- **A map with integer keys**, of any width signed or unsigned, is an object whose keys are the integers' decimals, as Go's and `serde_json`'s are. Its keys are written in the order of their values, `{"2":…,"10":…}`, as Rust's `BTreeMap` orders them; Go sorts them by their text, `"10"` before `"2"`, which reads wrong. Reading takes a key, its escapes decoded, only when it is an integer as JSON writes one, `-?(0|[1-9][0-9]*)`, and its type holds it: `"01"` and `"+1"` are refused, which Go's `strconv.ParseInt` and Rust's `str::parse` take, since JSON's grammar refuses them in a number and `Marshal` never writes them; `" 1"` is refused by all three. A key with an escape is decoded as a string first, so a broken escape is reported as in any string. A key given twice, `"1"` and `"\u0031"`, is an error, as it is in an object of string keys. Any other key type is refused where the program is compiled, `json.Marshal<map[bool]int>, json.writeValue<map[bool]int>: no arm of the match on K takes bool`. A map of a thousand integer keys encodes in 35 ns a key and decodes in 45 on either backend, against Go's 228 and 146.
- **An enum's layout** is chosen by attributes on it, as `serde`'s are. By default a variant is its name, or an object of one key holding its value. `@json.Tag("type")` writes the name under that key beside the variant's fields, `{"type":"Circle","r":1.5}`, `serde`'s internally tagged layout and the one most web APIs use for a choice of shapes; `@json.Tag("t") @json.Content("c")` puts the value under a key of its own, `{"t":"Pair","c":[1,2]}`, the adjacently tagged; `@json.Untagged` writes the value alone, `null` for a variant without fields, and reads the first variant, in the order declared, whose value the text is, as `serde` does, a variant that takes what an earlier one would never read back. Reading finds the tag wherever the object puts it, and the content under its key, left out or `null` for a variant without fields. A variant with a field keyed as the tag is refused by `Marshal` and `Unmarshal`, which compare constants the C compiler folds away for every other enum: the walk decides a part's name against a literal, and a tag's key is an attribute's value. Untagged reading tries each variant from where the value begins, so variants that hold the enum and differ only in a last field would double the time with each level of nesting, as `serde`'s do; the bytes failed tries read are bounded at 1024 times the text's length, past which the value is refused, so a text of a kilobyte can no longer take hours. What json cannot write is refused where the program is compiled with `refuse` (section 4), where `serde` refuses it with an error of its derive macro: `Content` without `Tag`, `Untagged` with either, a layout on a struct, and `Tag` alone on an enum with a variant whose field has no name, which `serde` takes for a variant holding one struct, flattening it, and refuses when it runs for any other value; Snello refuses both, and the field is named, or `Content` added. The default layout compiles to the same machine code as before the choice existed: the choice is a match on `attr` in place, which each backend writes as a constant the C compiler folds before it weighs what to inline, after a layout returned by a function was measured costing a decoded enum 2 ns in C, the call holding strings to drop on every path out.
- **Indented output**, `MarshalIndent(v, prefix, indent)` and `Indent(text, prefix, indent)`, has Go's layout: each element and member on a line begun with the prefix and the indent once per level, `": "` after a key, `[]` and `{}` kept, no prefix on the first line. `Indent` writes Go's bytes for the same text, and `MarshalIndent` for the same value, but where `Marshal`'s differ, `<`, `>`, `&`, U+2028 and U+2029, which Go escapes. `MarshalIndent` is `Marshal` and a pass over its compact text, as Go's is: `bench/json`'s `indent` writes a record in 627 ns on either backend against Go's 762. It differs from Go's twice. Space around the value is dropped, where Go's `Indent` copies the space after it to its output, which a layout has no use for; and `Indent` checks its text first and refuses invalid UTF-8, which Go's passes through, since every JSON text written as it is must be UTF-8.
- **Streams**, `Encoder` and `Decoder` over any `io.Writer` and `io.Reader`, are Go's `json.Encoder` and `json.Decoder`: `Encode` writes a value and a line break, in one write from a block the Encoder keeps; `Decode<T>()` reads the next value, `None` at the end of the input. A Decoder finds where a value ends by counting brackets and passing strings, then reads the value with `Unmarshal` where it lies in its block, through a view of the bytes as a string, so its rules, errors and speed are `Unmarshal`'s; the count is kept when the bytes read run out, so a value that comes in many small reads is looked through once. One large array or object is read a piece at a time with Go's state machine of what may come next, the commas and colons it passes between pieces: Go's `Token()` gives a token of any kind, one interface over delimiters, strings, numbers and booleans, where Snello's methods each read one kind, `BeginArray`, `EndArray`, `BeginObject`, `EndObject`, `Key`, and `Peek` tells the kind that comes next, as Go's `encoding/json/v2` `PeekKind` does, so an error says what was expected, `expected , or ]`, with its offset in the input. A reader's or a writer's failure is kept on the stream and returned by every later call, as `bufio`'s are, and `IoError()` gives it: kept in `json.Error` it would widen every `Result` the reader returns, which `bench/json` measured costing a decoded record 4 ns on LLVM. A value its type refuses is passed, and the next `Decode` reads the one after it, where Go's Decoder stops at a syntax error. `bench/json`'s `stream` writes a record through an Encoder and reads it back through a Decoder in 715 ns through C and 752 through LLVM, against Go's 1667.

## 7. What it costs

What runs for `Marshal<Point>` is what a programmer would write for `Point`: the field names as constants and a direct call for each field, open to inlining. Go's `encoding/json` walks the type's description for each value and calls through `reflect` for each field. `bench/json` encodes and decodes the same records to the same text with both: on an eight-core arm64 laptop a record encodes in 235 ns through either backend against Go's 436, and decodes in 317 ns through the C backend and 334 through LLVM against Go's 922 (`01-language-design.md`, the benchmark table). The compiler writes out each loop once per field and each arm once per type a program uses, as it compiles a generic function once per type now. The checker's walk runs only for a build that matches on a type, and a check of the examples, which do not, makes the allocations and takes the time it did before reflection.

## 8. Attributes

An attribute says something about a field, a variant or a type for a reflecting function to read: the name a field takes in JSON, that a field is left out when it is empty, a line of help a command-line parser prints. It is a constant, checked where it is written, and read while the program is compiled, so nothing of it is kept when the program runs:

```go
struct Server {
    Host  string                 @json.Name("host")
    Port  int = 8080             @json.Name("port")
    Tags  []string               @json.OmitEmpty
    Debug bool                   @json.Skip
}
```

- **An attribute is `@` and a constant of a type that lists `Attribute`.** Only a type a constant may have lists it, a number, a string, a bool or a struct of them, not generic: `G cannot be an attribute`. `Attribute` is a predeclared marker trait, as `Reflect` is, so a package says which of its types are attributes, as Java declares an annotation type: `type Name string impl Attribute`, `struct OmitEmpty impl Attribute {}`. The constant is any constant expression of such a type (`00-syntax-conventions.md`, Constants): a conversion, `json.Name("host")`, a struct literal of constants, a constant's name; a struct with no fields is written by its name alone, `@json.OmitEmpty`. `@5`, `@"host"` and `@json.Name(host)` with `host` a variable are refused where they are written, as any constant that is not one is, and so is an attribute of a type that does not list `Attribute`: `strings.Builder is not an attribute: it does not list Attribute`.
- **It is written after what it is about.** After a field's type, and its default when it has one, `Port int = 8080 @json.Name("port")`; after a variant and its fields, `Circle(r f64) @json.Name("circle")`, and a variant's field after its type, `Circle(r f64 @json.Name("radius"))`, as a struct's field; a function's parameter takes none; on a type, after its name, its type parameters and what it lists, before its body, `struct Options @Usage("the server's options") { ... }`, with `type Usage string impl Attribute` the program's own. A composite literal before a body is written in parentheses, `struct S @(Range{min: 1, max: 9}) { ... }`, as Go writes one in a condition, since the `{` there opens the body. Several are written one after another; two of one type on one declaration are refused, `json.Name is given twice`.
- **It says where it is written.** A type that lists `FieldAttribute`, `VariantAttribute` or `TypeAttribute`, predeclared traits that refine `Attribute`, is an attribute of those places alone, and is refused on the others: `json.Skip is not written on a type: it lists FieldAttribute`. A variant's field is a field. A type that lists only `Attribute` is written on any of them. An attribute written where nothing reads it would be passed over in silence, the flaw of Go's tags this design leaves out; Java's `@Target`, C#'s `AttributeUsage` and Kotlin's `@Target` say the same with an annotation on the annotation, and here it is a trait the type lists, as `Reflect` and `Attribute` are, with no syntax of its own.
- **It is read with `attr`.** The predeclared `attr(x, A)` gives the attribute of type `A` written on `x`, an `A?`: `Some` of it, or `None` when none is written. `x` is a part a loop over `fields` or `variants` gives, or a type parameter a `match` arm of `struct` or `enum` took, so `attr(f, json.Name)` reads a field's, `attr(c, json.Name)` a variant's and `attr(T, Usage)` a type's. In each copy of a loop written out per part, and in each instance of the function, it is written as a constant: `match attr(f, json.Name) { Some(n) => string(n), None => f.name }` is compiled for `Host` as a match on `Some(json.Name("host"))`, a constant the C compiler and LLVM may fold when they optimize; which attribute it is, and its value, are decided by the compiler alone.
- **It reaches what the field reaches.** An attribute is read wherever the field, variant or type it is written on is reached (section 3), and is a part of its declaration as its type is: an attribute of an unexported field of another package is read only where the field is, or where the type lists `Reflect`.
- **Not in this version:** an attribute on a function, a method, a parameter or a package, and an attribute that takes a type, as Rust's derives do. What reflection reads is the data a type is made of; a function's attributes would ask for code that runs on functions, which nothing here does.

The precedents: Go writes a field's options in a struct tag, a string the compiler does not check, so `json:"hots,omitempy"` is passed over in silence and the library parses the string each time it runs. Rust's `#[serde(rename = "host")]` is checked by the derive macro, outside the type checker, with names that are strings to the language. Java's and C#'s annotations are typed, as here, and read by reflection when the program runs; here they are read when it is compiled. Snello's are values of declared types, so a misspelt attribute is an unknown name, a wrong argument a type error, and a library's attributes are documented where it declares them.

Memory safe, no collector: an attribute is a constant, of the types a constant may have, held by the compiler in a table by the declaration it is written on, so that two packages' declarations at the same offset of their files never share attributes (after a table keyed by position gave one package's field another's); `attr` writes it in the code as any constant is written, and nothing of it is allocated, kept or freed when the program runs.

For maintainers: `@` is `token.AT`. The parser keeps a file's attributes beside its tree, `ast.File.Attrs`, by the field, variant or declaration each is written on, as `go/ast` keeps comments, so a node written without any is no larger (`parseAttrs`). The checker's `checkAttrs` in `compiler/types/attr.go` checks them once the impl lists are known: each a constant by the constant rules, a constant's name or the name of a struct with no fields, of a type that lists `Attribute`, none twice; it records them in `Info.Attrs` by the declaration they are written on, a type's name, a field or a variant, so that a `Var` grows by nothing; `Info.TypeAttr`, `FieldAttr`, `VariantAttr` and `VariantFieldAttr` find an instance's through its generic type's declaration. A conversion that keeps a string a string or a bool a bool is a constant expression for this, `json.Name("host")`. `attrCall` checks `attr`; `lower.AttrOf` finds the attribute a copy and an instance read, and both backends write it as `Some` of the folded constant, `Some` of the type's zero for a struct with no fields, or `None`.

## 9. JSON without a type: `json.Doc`, `json.Value` and `json.Text`

A program does not always know the type of the JSON it reads: a configuration with keys it passes through, a response it reads one field of, a document it edits. Go reads such text into `any`, a tree of `map[string]any`, `[]any` and `float64` the program then asserts its way through, with an allocation for every value and every number made a `float64`, so an ID past 2^53 comes back changed. Snello gives two kinds of untyped JSON, a borrowed view that reads and an owned tree that edits, and a field type, `json.Text`, that passes a value through as its text.

### `json.Doc`, a view of the text

`json.Parse(text ref string) Result<Doc, Error>` checks the text once and builds nothing but an index: where each value begins and ends, and where a container's values end. A `Doc` borrows the text, so the text outlives it, which the borrow checker holds a program to with no lifetime written; nothing in the text is copied.

A value of the document is a `json.Node`, an index into the `Doc`, and the `Doc` answers what each node is, as Snello's arenas answer for their indices (`02-arenas-and-indices.md`):

```go
doc := json.Parse(ref text)?
port := doc.At(doc.Root(), "/servers/0/port")         // an RFC 6901 pointer, a Node?
n := doc.Int(port ?? return Err(missing)) ?? 8080
for m := range doc.Members(doc.Root()) {              // in the order the text has them
    fmt.Println(m.Key, doc.Text(m.Value))              // ref strings into the text
}
cfg := doc.Decode<Config>(node)?                      // one part read as a type
```

- **What a node is.** `doc.Kind(n)`, and `doc.Bool(n)`, `doc.Int(n)`, `doc.Float(n)`, `doc.String(n)`, each an option, `None` for a node of another kind or a number its type cannot hold; `doc.Text(n)` the node's text as the input has it, a `ref string` with nothing copied.
- **Where its parts are.** `doc.Get(n, key)`, `doc.Index(n, i)`, `doc.At(n, pointer)`, each a `Node?`; `doc.Len(n)`; `doc.Elements(n)` and `doc.Members(n)`, loops over an array's elements and an object's members, a member's key a `ref string` into the text.
- **`String` copies; `StringInPlace` does not.** `doc.StringInPlace(n)` is the string's value read in place, a borrow of the text between its quotes with nothing copied, which it can give only when the string holds no escape, `None` when it does; `doc.String(n)` decodes the value into a string of its own either way, which outlives the `Doc`. A program reads keys, IDs and names in place and falls back to `String`, `doc.StringInPlace(n) ?? return slowPath(doc.String(n))`.
- **`Decode<T>(n)` reads one part as a type**, the typed decoder of this package over that part's text, so a program reads the one object it knows the shape of and leaves the rest untouched; an offset in its error counts from the start of the whole text.
- **Why an index and not a node holding the document.** A node that held a borrow of the `Doc` and handed out views of the text would need the borrow it returns to come from the one a value it was given holds, which Snello's rule for returned borrows does not reach: a returned borrow comes from a borrowed parameter (`04-borrows-ref-and-mut.md`). Rust says it with a lifetime on the node, `Node<'a>`, which Snello does not write. Every view a `Doc` gives is of its own `ref` receiver, which the rule reaches, and a node is a number a program may copy and keep.
- **The index is made in one pass.** It is built while the text is checked, a few words for each value; a skipped value is passed over in one step from the index, not byte by byte. A pass with SIMD in the C runtime, as simdjson finds the structural characters sixteen or thirty-two bytes at a time, is the next step if the measurement asks for it.

### `json.Value`, an owned tree

```go
enum Value {
	Null
	Bool(bool)
	Number(string)
	String(string)
	Array([]Value)
	Object([]Field)
}

struct Field {
	Key   string
	Value Value
}
```

- **A number keeps its text**, `Number(string)`, so a 64-bit ID or a long decimal round-trips exactly; `Int()` and `Float()` read it as wanted, and `Marshal` refuses a `Number` whose text is no JSON number. Go's `any` makes every number a `float64`.
- **An object keeps its members in order**, as the text had them, and is written back in that order, as C#'s `JsonNode` and `serde_json` with `preserve_order` do. `Get` finds a member by key, the first of a key given twice, as a `Doc` does; `Set` replaces a member in its place or adds it at the end, and `Remove` takes one out.
- **It is read and written as any type is**, `Unmarshal<json.Value>(text)` and `Marshal(ref v)`, or made from a node of a `Doc`, `doc.Value(n)`, and has `Kind`, `Len`, `Index` and `At` for a pointer, as a `Doc` does; a program matches on it for the rest, `match v { json.Number(t) => ..., json.Object(fields) => ... }`.
- **Its variants take JSON's names**, `json.Null`, `json.Object`, since a program builds and matches values far more than it compares kinds; `Kind`'s variants say what they are, `json.ObjectKind`.

### `json.Text`, a value passed through

A field of type `json.Text` keeps the text of its value as the input has it, checked to be one value, and `Marshal` writes it back compacted: a struct reads the part it knows and passes the rest on. It owns its text, since a field of a value `Unmarshal` returns cannot borrow the input (section 3); `t.JSON()` reads it, and `json.Text.Of(text)` makes one from text it checks. A program that wants the text without a copy reads it from a `Doc`, `doc.Text(n)`.

### Memory safe, no collector

A `Doc` borrows the text and is checked as every borrow is, and its nodes are numbers: the text cannot change or go while a `Doc` of it is used, and nothing is freed by a collector, since a `Doc` owns its index alone and a `Value` is a tree of owned values dropped once. The SIMD pass reads the text within its bounds, its last block padded, and writes only the index it owns.

### What it costs

`bench/json` measures, against Go's standard library, per record of a thousand: indexing the text with a `Doc` and reading each record's ID, 280 ns against `Unmarshal` into `any`, 2,449 ns; and a round trip through a `Value`, read and written back, 710 ns against one through `any`, 3,275 ns. A `Doc` makes one allocation for its index where Go's `any` makes one for every value.
