# Reflection at compile time

Status: designed.

Reflection is a function looking at the type it was given: which kind of type it is, a struct's fields by name, an enum's variants. With it, one function serves every type: an encoder for JSON, a printer for debugging, a diff of two values for a failed test, a parser of command-line flags into a struct, a loader of a configuration file. Without it, each of those is written again for every type, or generated by a tool.

In Snello all of it happens while the program is compiled. A generic function asks about its type parameter with `match T`, goes through a struct's fields with `for f := range fields(T)`, reaches a field with `v.[f]`, and builds a value from its fields. The compiler checks the function once, as it checks any generic function. When it compiles the function for a type, it keeps the one arm that type matches and writes the loop out once per field, each field's name a constant. What runs is the code a programmer would have written by hand for that type: no description of a type is kept in the program, nothing is looked up by a type's name, nothing goes through a table.

Package `encoding/json` in the standard library is written this way, and shows how any such library is.

## An example

Encoding, for any type the arms cover:

```go
func write<T>(v ref T, out mut strings.Builder) {
    match T {
        bool => out.WriteString(if v { "true" } else { "false" })
        i8 | i16 | i32 | i64 | int => out.WriteString(strconv.Itoa(int(v)))
        f64 => out.WriteString(strconv.FormatFloat(v, 'g', -1, 64))
        string => quote(mut out, v)
        E? => match v { Some(x) => write(x, mut out), None => out.WriteString("null") }
        []E => {
            out.WriteByte('[')
            for i, e := range v {
                if i > 0 { out.WriteByte(',') }
                write(e, mut out)
            }
            out.WriteByte(']')
        }
        struct => {
            out.WriteByte('{')
            first := true
            for f := range fields(T) {              // written out once per field
                if !first { out.WriteByte(',') }
                first = false
                quote(mut out, f.name)               // a constant string
                out.WriteByte(':')
                write(ref v.[f], mut out)            // the field, lent
            }
            out.WriteByte('}')
        }
        enum => match v {
            for c := range variants(T) => {         // one arm per variant: v holds c in it
                out.WriteString("{")
                quote(mut out, c.name)
                out.WriteString(":{")
                ...                                  // fields(c), as a struct's
                out.WriteString("}}")
            }
        }
    }
}
```

For `struct Point { X int; Y int }`, `write<Point>` is compiled as if it read:

```go
out.WriteByte('{')
quote(mut out, "X"); out.WriteByte(':'); write<int>(ref v.X, mut out)
out.WriteByte(',')
quote(mut out, "Y"); out.WriteByte(':'); write<int>(ref v.Y, mut out)
out.WriteByte('}')
```

and `write<int>` as the one line of its arm.

Decoding builds the value from its fields, each found in the input by its name, of the field's own type:

```go
func read<T>(r mut reader) Result<T, Error> {
    match T {
        ...
        struct => {
            r.object()?                              // notes where each key's value lies
            return Ok(T{ for f := range fields(T) {
                [f]: if r.key(f.name) { read<f.type>(mut r)? }
                     else { f.default ?? return Err(r.missing(f.name)) }
            } })
        }
    }
}
```

## The precedents

- **Go** reflects when the program runs: `reflect` reads a description of a value's type, kept in the binary for it, and `encoding/json` walks it for every value, which is why generators such as `easyjson` exist, to write the code per type the walk replaced. Struct tags rename a field, strings the compiler does not check.
- **Rust** keeps nothing at run time; `serde`'s derive macro writes code per type that hands each field to a serializer trait. Reflection is not in the language: it is a macro outside the type checker.
- **Swift** has `Mirror`, which reads a value's children when the program runs, and `Codable`, written by the compiler for a type that lists it.
- **Zig** gives a type's description at compile time, `@typeInfo(T)`, and an `inline for` over its fields that the compiler unrolls per type, which is what Snello does. Zig gets it by running any code in the compiler, `comptime`, a second language with its own rules; Snello gives the few things reflection needs and runs nothing in the compiler.
- **C++** checks a template for each type it is used with, so its mistakes appear at the use; Snello checks a reflecting function once, and only the questions a type can answer, which arm it takes and which fields it shows, are asked where it is used.

## 1. `match T`: which type

A `match` on a type parameter of the function, or of its receiver's type, chooses an arm by the type:

| Arm | Matches | In the arm |
|---|---|---|
| `int`, `string`, `f64` | that type alone | `T` is read as the arm's type |
| `i8 \| i16 \| i32` | any of them | the arm is checked once for each |
| `Point`, `List<int>` | that declared type | `T` is read as it |
| `E?`, `[]E`, `*E` | an option, a slice, an owned pointer | `E` is a type parameter of the arm's |
| `map[K]V` | a map | `K` and `V`, `K` with `Eq` and `Hash` |
| `struct`, `enum` | any struct, any enum | `T`'s fields or variants are reached |
| `_` | any other type | |

- **Arms are tried in order**, the first that fits taken: `Point` before `struct` handles `Point` its own way.
- **An arm naming a type takes that type alone.** A type declared over another, `type Celsius f64`, is a type of its own, as it is to assignment, and takes an arm that names it, its kind's, `struct` for a type declared over a struct, or `_`, never the `f64` arm: a `Celsius` written as an `f64` would lose what its name says, and an arm that wants every type declared over `f64` would have no way to name them. Go's type switch matches a declared type by its name alone, as here.
- **An arm reads `T` as what it matched.** `v` of type `ref T` in an `int` arm is a `ref int`, and in a `[]E` arm a `ref []E` whose elements are `E`. A shape's names, `E`, `K`, `V`, are type parameters of the arm, and a `match` on one of them is a match on a type as `match T` is.
- **It is not exhaustive by itself.** A type no arm matches is refused where the function is used with it (section 4); an arm `_` takes every type the others do not.
- **An arm takes no guard**, since a type is matched by what it is. A `match T` is a statement or an expression, as `match` is; as an expression, its arms give one type.
- **Not in this version:** an arm for an array's length or a tuple's elements. An array or a tuple is matched by its type, `[4]byte`, or by `_`.

## 2. Fields and variants

In a `struct` arm, `fields(T)` gives the struct's fields to a `for` loop, which the compiler writes out once for each:

- **`f.name`** is the field's name as declared, a constant string. **`f.type`** is its type, written where a type is, `read<f.type>(...)`, and matched with `match f.type`. **`f.default`** is its default (`00-syntax-conventions.md`, Default field values), an `f.type?`, `None` for a field that declares none.
- **`v.[f]`** is the field `f` of `v`, as `v.x` is the field `x`. It is lent: read through a `ref`, changed through a `mut`, never moved out of `v`, since the function cannot know whether `T` implements `Drop` (`00-syntax-conventions.md`, Destructors), and a field moved out of such a value would be read by its `Drop`. Its type is `f.type`, a type parameter of the loop with no bounds.
- **A value is built from its fields** by a literal with one loop in it, `T{ for f := range fields(T) { [f]: value } }`, which names every field, each given its line's value in the order of the fields; a `?` that leaves drops the fields made before it, as in any literal.
- **The loop holds no `break`, `continue`, `defer` or `select`.** It is written out once per field, and each copy is a block of its own.

In an `enum` arm, a `match` on `v` takes one arm written out once for each variant, so that it covers them all:

```go
match v {
    for c := range variants(T) => { ... }   // v holds the variant c here
}
```

- **`c.name`** is the variant's name, a constant string; `fields(c)` its fields, as a struct's, with `v.[f]` each field of the variant `v` holds.
- **The arm holds `v`.** Its fields are read as those of the variant `c`, so while the arm runs `v` is not assigned, moved or lent `mut`, `cannot assign to v: the arm written for each variant holds it`, as a pattern binding a variant's fields holds the value it matched.
- **A variant is built** by its constructor with one loop for its arguments, `c(for f := range fields(c) { value })`. Which variant to build from an input is found by its name: `for c := range variants(T) { if name == c.name { return Ok(c(...)) } }`, the loop written out once per variant.

## 3. What reflection reaches

Reflection reaches what code written by hand could, and a type opens itself to more by saying so:

- **A function reaches the fields its package can name**: every field of a type of its own package, the exported fields of another's. A struct of another package with a field the function cannot name is refused where the function is used with it, naming the field: `json.Marshal<Config>, json.write<Config>: field port of Config is not exported; export it, or list Reflect on Config`. Nothing is passed over in silence.
- **`Reflect` opens a type to every package.** A type that lists the predeclared marker trait `Reflect`, `struct Config impl Reflect { port int }`, has all its fields reached by any reflecting function, and may be built by one: its package says so where it declares the type. A type that does not list it keeps what it keeps, so an `rc.Rc`, an `os.File` or a `sync.Mutex`, none of which lists it, is never read or forged by reflection.
- **`Reflect` opens what its package declares.** A type declared over another package's struct, `type Mine refl.Own`, is a type of the program's, but the fields are `refl`'s: listing `Reflect` on `Mine` opens none of them, `field hidden of Mine is not exported by refl, which declares it`, since a package cannot open what another keeps.
- **A variant** is reached by the same rule as a field: an enum of another package with a variant the function cannot name is refused unless the enum lists `Reflect`. A variant's fields are reached where the variant is, by their place, as a pattern of another package binds them whatever their names.
- **A field that holds a borrow** is refused where the function is used with its type, as any type argument holding a borrow is: `field src of Decoder holds a borrow, ref string`.

## 4. Where the questions a type answers are asked

A reflecting function is checked once. What depends on the type it is used with is asked by the checker, after the package's functions are checked, for each type a reflecting function is used with, directly or through another generic function: from every call with types known, it follows the calls of generic functions inside, with the types each is given, through the arms each type takes and the fields each loop gives. Each question is asked once per function and type, and a mistake is reported once, at the call the program wrote, with the chain that led there:

- **No arm matches.** `json.Marshal<Server>, json.write<Server>, json.write<chan int>: no arm of the match on T takes chan int`.
- **A field or variant is not reached** (section 3), or holds a borrow.
- **The types grow without end.** A function given a type that holds the type an earlier call of it on the chain was given, which holds the type a call before that was given, so that the types have grown twice through its arms, is refused: `f<int>, f<[]int>: f<[][]int> holds f<[]int>, which holds f<int>; the types grow without end`. A recursive type, an enum `Value` holding `[]Value`, does not grow: `write<Value>` asks for `write<[]Value>`, which asks for `write<Value>`, already asked for.
- **The calls go deeper than the checker follows.** A chain of more than 256 calls of generic functions, each with types not asked about before, is refused at the call it began from, naming its ends, `f0<string>, ..., f255<string>, f256<string>: the calls of generic functions go deeper than 256, more than the compiler follows`, so that every instance a backend compiles has been asked about.

The backends ask the same questions of the same function in `compiler/types`, so the arm a type takes and the fields a loop gives are decided in one place, and the program that checked is the program that is compiled. `snello check` reports all of it.

## 5. Memory safe, no collector

Reflection adds no kind of value and nothing to the program when it runs. A reflecting function is a generic function: checked once against the rules every function is checked against, then compiled per type with its loops written out, so what runs is ordinary code over ordinary values, each owned once and dropped once.

- **A field is lent, never moved** (section 2), so a `Drop` never reads a field reflection took.
- **A value is built by a literal naming every field**, so no zero is made of a type without one and no value is half made; a `?` drops the fields made before it.
- **Nothing is forged.** A type is built from its fields only where a literal of it could be written, or where its package listed `Reflect`.
- **No borrow is stored.** A field holding a borrow is refused where it would become a type argument.
- **No description of a type at run time.** The names are constant strings in the code written per type, read only by it.

## 6. `encoding/json`

Package `encoding/json` is written over reflection, with nothing per type: `Marshal<T>(v ref T) Result<string, Error>`, which refuses only a float JSON has no text for, a NaN or an infinity, as Go's does, and `Unmarshal<T>(text ref string) Result<T, Error>`, with `Error` saying what could not be read and at which offset. A struct is an object of its fields; an option `null` or its value; a slice an array; a map with string keys an object, its keys sorted, as Go's are; an enum's variant without fields its name, `"Null"`, one with one unnamed field an object of one key holding the value, `{"Bool":true}`, one with several an array, `{"Pair":[1,2]}`, and one with named fields an object of them, `{"Circle":{"r":1.5}}`, as `serde`'s default is. Decoding finds each field by its key, wherever the input puts it, and passes over a key the type has no field for, as Go's does; a field missing from the input is an error at the object it is missing from, unless it is an option, `None`, or declares a default, which it takes; a number its field's type cannot hold is an error, `300 overflows its field`; a key given twice is an error, as Go's `encoding/json/v2` makes it.

- **The text is held to JSON's grammar**, as Go's and `serde_json`'s readers hold it: a member without its comma, a number JSON does not write, `01`, `+1`, `.5`, `1.`, a raw control character or a broken `\u` escape in a string, and text after the value are errors with their offset. A `\u` half of a pair without its other is U+FFFD, as Go reads it.
- **Nesting is bounded at 128**, `serde_json`'s limit, in a value read and in one passed over: a task's stack does not grow, and each level the reader goes into takes a frame of it, so a text of ten thousand `[` is an error, `exceeded max depth`, not a crash. Go's reader nests to 10000 on a stack that grows.
- **A float is written as Go's `encoding/json` writes it**: its shortest text, in plain decimals from `1e-6` up to `1e21` and with an exponent outside, `1e-7`, `1e+21`; an `f32` by its own shortest text, `0.1`, not the `f64`'s.
- **A string is written as it is**, with `"`, `\`, the control characters escaped and a byte of invalid UTF-8 written `\ufffd`, as Go writes it. Nothing is escaped for HTML, as `serde_json` writes it: Go's escapes `<`, `>` and `&` by default, for a text pasted into a page, which a library for data has no reason to assume.
- **An owned pointer, `*E`,** is the value it points at, and reading one allocates it, so a recursive struct through a pointer, `struct Node { V int; Up *Node? }`, round-trips.

## 7. What it costs

What runs for `Marshal<Point>` is what a programmer would write for `Point`: the field names as constants and a direct call for each field, open to inlining. Go's `encoding/json` walks the type's description for each value and calls through `reflect` for each field. `bench/json` encodes and decodes the same records to the same text with both: on an eight-core arm64 laptop a record encodes in 235 ns through either backend against Go's 436, and decodes in 317 ns through the C backend and 334 through LLVM against Go's 922 (`01-language-design.md`, the benchmark table). The compiler writes out each loop once per field and each arm once per type a program uses, as it compiles a generic function once per type now. The checker's walk runs only for a build that matches on a type, and a check of the examples, which do not, makes the allocations and takes the time it did before reflection.
