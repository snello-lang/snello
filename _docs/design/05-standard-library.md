# The standard library

Status: decided. This note says what the Snello standard library is: which names the language itself knows, where every other name comes from, how the library relates to Go's, and the rules every library signature follows. It exists because the twenty example programs use library names that no other document defines, and the checker needs the answers. The decisions with no precedent to follow are marked **decided** below with the reason. Everything else follows a precedent named in place.

## The precedents

Three languages define the space, and Snello follows Go wherever Go has an answer, as the syntax conventions require.

- **Go** keeps the language's own vocabulary to a few dozen predeclared identifiers, `len`, `make`, `append`, `error` and the basic types, and puts everything else in packages that must be imported. There is no prelude.
- **Rust** makes `Option` and `Result` library types but imports them through a prelude, and the `?` operator is language syntax that knows them.
- **Swift** does the same with less ceremony: `T?` is sugar for a library enum, and the standard library is imported implicitly.

Snello takes Go's shape, a short predeclared list and no prelude, with Swift's sugar for the option type, which the syntax conventions already fixed as `T?`.

## 1. What the language knows

These names are predeclared: visible in every file without an import, and known to the compiler. The list is deliberately short and this section is its only home; the checker's universe scope is built from it.

**Number types.** The short names used by Rust, Zig, Odin, Hare, Carbon and by LLVM itself, plus Go's everyday words. This is the one place Snello's vocabulary departs from Go's on purpose: Go's syntax and keywords are what make Snello readable at first sight, while the spelling of a primitive type is vocabulary, and vocabulary is where a language shows it is not a dialect.

| Kind | Types |
|---|---|
| Signed integers | `i8`, `i16`, `i32`, `i64`, `int` |
| Unsigned integers | `u8`, `u16`, `u32`, `u64`, `uint` |
| Floating point | `f32`, `f64` |
| Aliases | `byte` for `u8`, `rune` for `i32` |

`int` and `uint` are the word size of the platform and `int` is the index type, as in Go, so there is no `usize`. `byte` and `rune` name a meaning rather than a width and stay because strings are UTF-8 as in Go. Integer arithmetic wraps on overflow as in Go; checked arithmetic is a method returning `T?`, `CheckedAdd`, `CheckedSub` and `CheckedMul` on every integer type, not a language mode. There is no `i128`, no complex type and no `uintptr`: the first two are library types if ever needed, the third waits for the foreign-function boundary. Literals take the type their context asks for; there is no untyped constant arithmetic in the first version.

**Other basic types.** `bool`, `string`, `error`.

**Option and result.** `T?` with `Some` and `None`; `Result<T, E>` with `Ok` and `Err`. Both are enums the compiler knows, because `?` and `??` and `match` exhaustiveness are language features over them. Their methods: `Expect`, `Unwrap`, `UnwrapOr`, `UnwrapOrElse`, `IsSome`, `IsNone`, `IsOk`, `IsErr`, `Map`, `MapErr`, `AndThen`, `OrElse`, `Ok`, `Err`. The ones that give the inside away take their receiver; the tests lend it.

**Functions.** `len`, `cap`, `make`, `take`, `replace`, `panic`, `print`, `min`, `max` (`min` and `max` as Go has them since 1.21; `replace` moves a value out of a place and leaves another, for a type with no zero value as for any).

**Methods on the built-in collection types.** Go cannot declare a method on a built-in type, so it hides these behind `append`, `delete` and the `strings` package. Snello puts them on the value, which is what the examples already write.

| On | Methods |
|---|---|
| `[]T` | `Push`, `Pop`, `Insert`, `Remove`, `RemoveValue`, `Clear`, `Swap`, `Reverse`, `Sort`, `SortBy`, `Contains`, `Index`, `First`, `Last`, `Extend`, `Truncate`, `Clone`; on `[]byte`, `Equal` and `Find` too. `Swap(i, j)` exchanges two elements in place, Rust's `slice::swap` and the `Swap` of Go's `sort.Interface`: the move an algorithm over elements that are not `Copy` makes, since `xs[i], xs[j] = xs[j], xs[i]` would move each out of the slice. Runs are merged by powersort's stack, trimmed of what is already in place, picking each element with a select. The buffer is half the slice, where Rust's is the whole slice up to 8 MB, for the low memory footprint Snello wants: one more merging pass on large unordered input. A comparison that is not a consistent order, a NaN or a function that contradicts itself, leaves an unspecified order but every element in the slice once, where Rust panics; Go makes no promise. `Reverse` swaps likewise, and `Push` with room and `Pop` of a slice that owns its elements are written inline, the runtime called only to grow or to panic. Each sort of a program is instantiated once per element type and order, as Rust's generic sort is: both backends write a function for it that calls the runtime's sort, which is inlined whole into that function when the program is optimized with the runtime, so the element's size and the comparison are constants there and the comparison is inlined, not called through a pointer. `SortBy` given a closure calls it, as Go's `slices.SortFunc` does. Sorting a million random numbers takes 1.25 times as long as Rust's driftsort and 0.3 times as long as Go's unstable pdqsort, and a million records with a thousand distinct keys 1.5 times Rust's and a ninth of Go's. A sub-slice `xs[lo:hi]` has the type of a slice and lends its slice's buffer, so the methods that change the length, and replacing it, panic on one (after the review of the standard library found them corrupting the slice they were cut from); the check is the runtime's, as an index check is, since a function given `mut []T` cannot know which it holds |
| `map[K]V` | `Get`, `GetMut`, `GetOrInsert`, `Insert`, `Remove`, `Contains`, `Clone`. `m[k]` on a missing key reads the zero value and changes nothing; `m[k] = v` and `m[k] += v` make the entry. A range visits entries in insertion order. The table is Rust's `indexmap` over a Swiss table (after an audit measured the first one behind Go and open to HashDoS): the entries in insertion order with each key's hash, and an index of control bytes, seven bits of the hash a slot, probed eight at a time, at most seven eighths full; one hash and one probe find or insert a key. Keys are hashed by wyhash keyed with a seed from the system's random source, as Go's maps are when they have no AES. Measured against Go's and Rust's maps on a million `int` keys, delete-heavy churn and iteration, it is ahead of both; on 64-byte string keys too |
| `string` | `Len`, `Clone`, `Fields`, `Lines`, `Split`, `SplitN`, `SplitOnce`, `Trim`, `TrimSpace`, `TrimPrefix`, `TrimSuffix`, `HasPrefix`, `HasSuffix`, `Contains`, `Index`, `LastIndex`, `Count`, `Replace`, `ReplaceAll`, `ToUpper`, `ToLower`. `Contains`, `Index`, `LastIndex`, `Count`, `Replace`, `Split`, `SplitN` and `SplitOnce` find a text of two bytes or more by its first two bytes, eight places at a time, as glibc's `memmem` filters a short needle, counting the bytes each failed comparison cost, and hand the rest of the text to the Two-Way search of Crochemore and Perrin, the one glibc, musl and Rust's `str::find` make, once that cost outruns what the search moved, eight to a byte, with a few hundred and four lengths of the needle to start, so that one near miss does not hand the rest over: no needle makes a search more than linear in the text and the needle, with no table and nothing allocated (after a review timed a pattern of period sixteen, 50,001 bytes in 20 MB, at 1.6 s by the Rabin-Karp fallback that came before, which counted failures and not their cost, against 0.02 s by Two-Way; Go's `strings.Index` takes 1.3 s on it). One byte is `memchr`. White space below 0x80 is found by Go's `asciiSpace` table, and `Fields` over ASCII text counts its fields first and makes its result once, as Go's does; `ToUpper` and `ToLower` change an ASCII byte by arithmetic, and copy the text even when nothing changes, since the result is owned and the text may be another's. `+` over a chain, `a + "-" + b`, is one allocation, as Go's `concatstrings` makes; `s += t` writes in place when `s` owns the room and else into a block twice as large, as Rust's `String` grows, an owned string's capacity being its block's size (after an audit measured each `+` allocating and `+=` copying the whole every time) |
| `byte` | `IsDigit`, `IsSpace`, `IsLetter`, `IsUpper`, `IsLower`, ASCII |

**The everyday methods.** The methods every program reaches for beside those above, on Snello's terms: a search that may find nothing returns `int?`, never `-1`; a method that can only cut lends its receiver, `ref string` into it, and never allocates; a method given a count it cannot honour does the nearest thing a count means, never panics, and never reads a negative count as "all", which has its own name; and each is written on the algorithm the method beside it already uses, so none is slower than the one a program would otherwise write.

| `[]T` | `Index(v ref T) int?` | the position of the first element equal to `v`; `T` is `Eq` | `memchr` for an element of one byte compared as its byte, a type over one that writes its own `Eq` excepted; a plain loop over the element's equality otherwise, as Go's `slices.Index` is |
| `[]T` | `First() ref T?`, `Last() ref T?` | a borrow of the first or last element, `None` when empty | a length test and a view |
| `[]T` | `Truncate(n)` | the elements from `n` on dropped, the capacity kept; `n >= len` does nothing and `n <= 0` empties it | each dropped element's `Drop` run, first to last, as `Clear` runs them, then the length set |
| `[]byte` | `Equal(o ref []byte) bool` | whether both hold the same bytes | a length test and `memcmp` |
| `[]byte` | `Find(sub ref []byte) int?` | the offset of the first run of bytes equal to `sub`; `Index` stays the search for one byte, as on every slice | the search `string`'s `Index` makes, over the bytes |
| `map[K]V` | `GetOrInsert(k, v) mut V` | the value at `k`, inserting `v` first when `k` is absent; `k` and `v` are dropped when the key is there | one hash and one probe, the slot the table finds or makes |
| `T?` | `AndThen<U>(f func(v T) U?) U?`, `OrElse(f func() T?) T?` | `f` of the value, or the option itself; the option itself, or `f`'s | taken, as `Map` takes it; written inline, the function called directly, no allocation |
| `Result<T, E>` | `Ok() T?`, `Err() E?` | the half there is, the other dropped | taken; a branch and a move |
| `Result<T, E>` | `AndThen<U>(f func(v T) Result<U, E>) Result<U, E>`, `UnwrapOrElse(f func(e E) T) T` | `f` of the value, or the error passed on; the value, or `f` of the error | taken, inline as `Map` |
| every integer type | `CheckedAdd(o) T?`, `CheckedSub(o) T?`, `CheckedMul(o) T?` | the result, `None` when it does not fit, which section 1 promises | the overflow-reporting add, subtract and multiply both backends' compilers have, one instruction and a test of its flag |
| the signed integers | `Abs() T` | the magnitude; the minimum, which has none in the type, stays itself, as the language's arithmetic wraps | branchless: a negate and a select |
| every integer type | `Clamp(lo, hi) T` | the value held between `lo` and `hi`; `hi` when `lo > hi` | `min(max(x, lo), hi)`, two selects |
| tuples and options | `Eq` through a bound | `a.Eq(b)` on a `T: Eq` that is a tuple or an option, which `expect.Equal` calls, as `==` already compares them | the comparison `==` writes, called by name |

`Index` means one thing on every slice, the search for one element, `[]byte` included, so a generic function over `[]T` finds the same thing whatever `T` is; the search for a run of bytes is `Find`, the name Rust gives it on a byte slice beside `find_byte`. A string's needle is always text, so on `string` it is `Index`.

The checker states each method's bound on the element: `Contains`, `RemoveValue` and `Index` need `Eq`, `Sort` needs `Ord`, and `Extend` and `Clone` need `Clone`, as a generic function's bound is asked; a map's `Clone` asks `Clone` of its keys and values. A slice whose own elements meet `Eq` meets it, compared element by element, as `library-corners` has always searched a `[][]int`; a borrow meets `Eq` when what it views does, and `Clone` always, so the pieces `Split` and `Fields` lend are searched and copied; and a `Copy` element meets `Clone`. The rest is refused at `snello check`, `Contains needs the elements to be Eq: P is not`. That is tighter than before: a struct that lists no `Eq` was searched by its fields, which `==` refuses, a slice or a map of a type that lists no `Clone` was cloned by its fields, which a `File` shared its descriptor through, and `Sort` of a struct reached the backends, which reported it as a construct they did not support.

The pieces `Split`, `SplitN`, `Fields` and `Lines` lend are borrows of the string, and so is the slice that holds them, for as long as it is used, as a variable holding a `ref string` is: the string cannot be changed, moved or dropped while the pieces are still to be read, and a slice cloned from them holds it too. `Push`, `Insert` and `Extend` on such a slice store more borrows, and the slice holds the string each came from (`storedElement` in `compiler/types/call.go`). Before, the checker did not count a slice as holding a borrow at all, since a program cannot write one, and `parts := s.Split(","); s = t` read freed memory.

`Extend` and `Clone` copy an element with `memcpy` when its clone is its bytes: it is `Copy` and no type in it writes a `Clone` of its own (`lower.ClonesAsBytes`). Any other element is cloned one by one, so that a `Clone` the type writes runs, as a derived `Clone` calls a field's own (`standard.snello`'s `Ver`), at any depth: a `Copy` struct over such a field, a tuple, an option, a result, an array or an enum holding one; the integers, a `bool` and a struct of them stay one copy. A `Result` clones the half it holds, which before reached the backends as a construct they did not support.

**The standard traits.** `Copy`, `Clone`, `Eq`, `Ord`, `Hash`, `Drop`, `Error`, and the operator traits `Add`, `Sub`, `Mul`, `Div`, `Rem`, `Neg`. Every number type is `Copy`, `Eq`, `Ord` and `Hash`, and implements the operator traits.

**Decided 1: predeclared.** The collection methods are predeclared with their types, as above, because Go's `append` and `len` are, and because `xs.Push(v)` with an import line above it would surprise a Go developer. The alternative was a package the program imports for them.

## 2. No prelude: everything else is imported

Go's rule, and the rule the design's "what Snello leaves out" table implies, since a prelude is an implicit. Every type and function not in section 1 lives in a package and is named through it: `arena.Index<Node>`, `sync.Arc<T>`.

## 3. Go's package map, Snello's signatures

Package names and layout are Go's, so a Go developer knows where to look. Inside a package the rule is: **the same name when the meaning is the same, a new name when ownership changes the meaning.** `strings.Repeat` is the same function in both languages. `os.ReadFile` is not: Go's returns a byte slice and a nullable error, Snello's returns `Result<string, io.Error>`, so it is `os.ReadToString`. Kotlin treats Java's library the same way: the same names where nothing changed, new ones where null safety did. Two string methods keep a Go name for a different meaning, recorded here so that the difference is known (found by the review of the standard library): `s.Trim()` is Go's `strings.TrimSpace`, not its `strings.Trim`, which takes the bytes to cut; and `s.Lines()` drops each newline, where Go 1.24's `strings.Lines` keeps it. Renaming them, to `TrimSpace` and to a name of their own, is not decided; until then the book and `std/builtin` say so beside each. **Go is a map, not a specification:** Snello is a language setting its own course, so no package pins its output to Go's, a test's expected output is the language's own and reviewed as the book is, and conformance with Go holds only where a decision in this note says "as Go's"; a task proposing a Go twin for a package is refused on this sentence. Everything else in `strings` and the string methods reads text as Go does: case by Unicode's simple mapping and white space by Unicode's `White_Space` property, as Go's `unicode` package reads them, from tables `runtime/mkunicode.go` writes out of the Unicode Character Database itself, `UnicodeData.txt` and `PropList.txt` at the version it names, so Snello's Unicode follows the standard and not the toolchain that builds the compiler, a byte that is not UTF-8 as U+FFFD, and a search in time in proportion to the text.

## 4. Three signature rules

Every library function follows these, so a reader can predict a signature from a function's meaning. They are Rust's conventions in Snello's words, and they follow from `04-borrows-ref-and-mut.md`.

1. A parameter that is only read is `ref T`: `strings.Repeat(s ref string, n int) string?`, `fmt.Println(args ...ref any)`.
2. A parameter that is changed is `mut T`: `sort.Sort(xs mut []T)`, `fmt.Fprintln(w mut io.Writer, args ...ref any)`.
3. A parameter that is kept, stored or sent is taken by value, which moves it: `Push(v T)`, `arena.New(v T) Index<T>`, `sync.NewArc(v T) Arc<T>`.

Results are owned. `Copy` types are by value everywhere, and for them rule 1 reads as plain pass-by-value, as in Go.

## 5. The call-site rule

Rule 1 forces one language decision. The borrows note today says a borrow at a call site is written with the keyword, `strings.Fields(ref job.text)`, and every print call in the examples passes owned values without it: `fmt.Println("error:", e)`. Under the written rule that call moves `e` into `Println`, which is not what anyone means.

**Decided 3: yes.** An owned value passed where a `ref T` parameter is expected is borrowed for the call, exactly as a receiver already is: `x.Describe()` borrows `x` with no keyword. `mut` stays explicit at every call site, because a visible mutation is worth a word, as Go's `&x` and Swift's `&` are. Writing `ref` at the call site remains legal and means the same thing. With this rule the print calls are correct as written; the borrows note states the rule beside its call-site example.

## How the library is built

The library is Snello source under `std/`, one directory per import path holding one file named after the package, `std/math/math.snello`, embedded in the compiler binary so that a build needs no library path and no environment, as Go's toolchain carries its own standard library. When a program imports a path the compiler's table does not answer, the importer (`importer.Importer` in `compiler/importer/`, the counterpart of `go/importer`) parses and checks that package once, into the same `types.Info` as the program, and the C backend compiles the package with the program into the one C file, each of its top-level names qualified by the import path in the runtime's reserved space: `math.Sqrt` is `sn_math_Sqrt`. There is no separate compilation and no library binary; a Snello program is one translation unit, which is what lets the C compiler inline across the boundary.

A library function the runtime must provide is declared without a body, as a Go function implemented in assembly is, and the runtime defines it in C under that same qualified name: `func Sqrt(x f64) f64` in package `math` is `double sn_math_Sqrt(double)` in `snello.h`. A library variable declared without a value is the runtime's the same way: `var Args []string` in `os` is filled by the runtime at start-up. The runtime's side of `os` is small and primitive on purpose: each function takes a descriptor and returns the system's error number, zero on success, storing its result through its last parameter, and the Snello code builds the `Result` and the `io.Error`. A program may not declare a function without a body; the checker reports `missing function body`. Only the exported names of a package are visible to the program, by Go's capitalization rule, and so are only the exported fields and methods of its types; an import of a path the library does not have is reported at the import.

`io.Error` is a struct: the operation, the path and the system's reason, with a `Kind` the program can match on, `NotExist`, `Permission`, `Exists`, `Refused`, `Reset`, `TimedOut`, `Other`, and `Error()` giving Go's wording. **A socket's Error is Go's `net.OpError` in the same struct** (after the review of the standard library found network errors told apart only by their text): `Path` is the network and address, `tcp 127.0.0.1:1`, or both ends of a connection, `tcp 127.0.0.1:50338->127.0.0.1:8080`, and `Msg` names the system call before the system's reason, so the line reads as Go's, `dial tcp 127.0.0.1:1: connect: connection refused`; the three kinds a network program acts on, a refused dial, a reset or broken connection and one timed out, are `Kind`s rather than a type of `net`'s own, since a program matches on a `Kind` already and Go's own test, `errors.Is(err, syscall.ECONNREFUSED)`, is a test of the error number. An address is an IPv4 address and a port from 0 to 65535: an empty host is every address for `Listen` and this machine for `Dial`, as in Go, and a port out of range, a host name and an IPv6 address are refused with an Error that says which, `listen tcp: address 70000: invalid port`; looking names up and IPv6 are later work. It implements the standard trait `Error`, which its own name shadows inside package `io`; the syntax conventions resolve a trait's name as a trait for that reason. `io.Errno(op, path, code)` builds one from an error number, which is how `os` reports. `io.Reader` and `io.Writer` are traits with one method each, and `io.Copy` is generic over them, since a borrowed trait value is not a type yet.

Every package is a `.snello` file under `std/`, the ones the compiler writes included (A reader expects `std/` to list the whole library, with the documentation where Go puts it). `std/fmt/fmt.snello` declares `Println`, `Printf`, `Sprint`, `Sprintf`, `Fprint`, `Fprintln` and `Fprintf` without bodies, with `...ref any` for the arguments the compiler takes by their types, and the backend writes each call from a table of those seven names and `os.Exit`, and the functions of `math/bits` from their names, each as an instruction; the checker holds no table of library names at all. `fmt` is the compiler's by design: its functions take arguments of any type and the compiler lowers each by its type, so there is no formatter in the runtime. `Fprint`, `Fprintln` and `Fprintf` are generic over `W: io.Writer`, since a borrowed trait value is not a type yet, and the backend writes the formatted text with one call of the type's `Write`. `os.Exit` is declared `func Exit(code int)` and the checker knows the call never returns, as it knows of `panic`, until a signature can say so.

`arena` is written in Snello with no runtime at all: `Arena<T>` is a slice of slots, each an `Option` of the value and a generation, a free list of slot numbers and a count; `Index<T>` is the slot number and the generation, `Copy`, `Eq` and `Hash`, with `T` as a phantom parameter so an index carries its element type. Generations start at 1 so that the zero `Index` names nothing. `Get` and `GetMut` match on the slot's `Option` through a borrow of the arena, and `Remove` takes the value out with `take` and raises the generation. `New<T>()` takes its type argument explicitly where nothing infers it, as the LRU example's `slots: arena.New()` would need; the iteration `for i, v := range a` of `02-arenas-and-indices.md` waits for the iterator trait.

`rc` is written in Snello over functions the compiler provides for it alone, as the handles bullet of `sync` below says of both packages: `Rc<T>` and `Weak<T>` each hold the shared cell's address, `cell int`, and `cellType [0]*cell<T>`, which holds nothing and gives the handle the cell's type, so that the cell's `local` field keeps a handle in its task. The cell holds the strong and the weak count and the value untagged, the strong count saying whether it is there. `Clone` and `Downgrade` raise a count through `rawMut`; `Drop` lowers one, and the last `Rc` moves the value out with `moveOut` and drops it, counting itself one more `Weak` meanwhile, since the value's drop may drop `Weak`s on the same cell, and the last handle of either kind frees the cell with `rawFree`; `TryUnwrap` moves the value out of a cell it alone holds and gives its handle up with `leak`, its count spent. `Get` lends the value through the cell's address, with no case for a handle without one; `GetMut` lends it only when the strong count is 1 and the weak count 0, since a `Weak` elsewhere could otherwise be upgraded and read while the `mut` borrow lives. There is no interior mutability: a tree whose nodes hold `Weak` links back to their parents cannot be built with `Rc`, since a node is shared by the time its link is set, and a lock, the other way to change a shared value, holds only a value that is `Send`, which an `Rc` is not; that tree is the arena's, as `examples/tree/README.md` says. An `Rc` and a `Weak` implement `fmt.Stringer` and print as the value they hold, a `Weak` whose value is gone as `rc.Weak()`; no handle is empty. An `Arena` implements `fmt.Stringer` too and prints the values it holds in slot order, `arena[a b c]`, rather than its slots and generations.

`bufio` is written in Snello over `io`'s traits: `Writer<W: io.Writer>`, `Reader<R: io.Reader>` and `Scanner<R: io.Reader>` each hold a `mut` borrow of the value under them, so they are borrow-holding structs under the rules of `00-syntax-conventions.md`, lent and dropped but never stored, and `NewWriter(w mut W)` returns one tied to its one borrowed parameter. `Writer` implements `io.Writer` and `Reader` implements `io.Reader`, so `fmt.Fprintln` and `io.Copy` take them; for that the rule on type arguments gained its one exception, a generic function that only borrows values of a type parameter takes an argument holding a borrow (`lentOnly`). The buffer is a byte slice written out in blocks of 4096 bytes; the scanner keeps the unconsumed tail and reads a block when it has no newline, never more than its limit leaves room for, so a line past the limit is refused whatever the reader gives at a call, as Go's scanner reads into a buffer no larger than its limit; it strips `\n` and `\r\n`, and counts a last line without one. A `Reader` at the end of the input asks the reader under it again at the next call, as Go's does, so a file being appended to is read on; a `Writer` returns the error it keeps for an empty write too, and `NewWriterSize(w, 0)` is `NewWriter`. A range over a scanner's lines, as the grep example writes it, waits for the iterator trait; the Go idiom `for sc.Scan()` stands until then.

Map<U>(f func(v T) U) U?`. It is never compiled and its import is refused. The objection to a second statement of the signatures, that it drifts, is answered by a test: `TestBuiltin` under `std/` checks the file's methods as methods of holder structs and compares each with the checker's table, receiver mode, parameters and result, and reads the table's `case` names back to find a method the file omits. The file is thus the written specification of the predeclared surface, which the checker had only as code. Writing it found a parser gap: an optional tuple, `(ref string, ref string)?`, parsed as a parameter type but not as a result, so `SplitOnce`'s own signature could not be written; `parseResults` takes the `?` now.

Written in Snello: `math`, `io`, `os`, `strconv`, `strings`, `sort`, `time` but for `After` and `Tick`, which hand a `Time` over a channel, `arena`, `rc` over its two compiler-provided primitives, and `bufio`; `fmt` is declared there and written by the compiler, and `builtin` documents the predeclared names. `sort.Sort` is the slice's `SortBy` with the element type's `Cmp`, and `time.Duration` is a number type over `i64`, so a `Duration` is written as a product with a constant, `10 * time.Millisecond`. **Decided 5: `sync`.** The package is written in Snello over nine bodiless runtime functions and three the compiler lowers, and four facts of the language shaped it:

**Decided 6: `fmt` prints as Go's does, and checks its formats when the program is compiled.** A float prints in Go's shortest form, `strconv.FormatFloat(f, 'g', -1, 64)`, with Go's rule for the exponent, an exponent from a million up and below 0.0001, and `+Inf`, `-Inf` and `NaN`; an `f32` with the fewest digits that read back as the same `f32`; the digits are Ryū's, as Go's `strconv` finds them (after an audit found the first method, which tried precisions with the C library until one read back, 43 times slower than Go and longer than Go's text at 46 powers of two): a port of Go's `ftoaryu.go` over the powers of ten `runtime/mkpow10.go` writes into `runtime/c/pow10.c`, Go's `detailedPowersOfTen`, which prints all 272,049 floats of the audit's test set as Go does and a million of them as fast as Go; `%.2f` and `%.3v`, a float with a precision, are Go's `ryuFtoaFixed64`, the number scaled to the digits asked for with one 128-bit multiply and rounded half to even on its exact value, for up to seventeen significant digits, which Go itself uses for `%e` and `%g` and not `%f`, and past them every digit of the float, its mantissa times its power of two worked out in decimal and rounded where the precision ends, Go's `decimal` (when those went to the C library's `printf`, a program whose locale a bound C library had set to one that writes a comma printed `%.20f` of 1.5 as `1,50000000000000000000` and `%.20v` as `1.,5`, and `%.3f` of a number of twenty digits took 1.41 s for two million against Go's 0.22 s; 0.27 s since), so no float is read or written by the C library; twenty thousand doubles of every magnitude print in every one of those forms as Go prints them, and `Sprintf` of a line of four verbs is faster than Go's; `%q` escapes as `strconv.Quote` does, over the printable runes as Go's `strconv.IsPrint` defines them, a letter, a mark, a number, a punctuation or a symbol, or the ASCII space, which the runtime carries in `runtime/c/unicode.c`, written by `mkunicode.go` from the Unicode Character Database with the case tables. The verbs are Go's `%v`, `%d`, `%s`, `%q`, `%f` and `%t`, and `%x`, `%X`, `%o` and `%b` for an integer in a base, `%c` for one as its character, and `%e` and `%g` for a float, with a width, a precision, the minus flag and the zero flag. `%x` and `%X` take the bytes of a string or a `[]u8` as well, which is how a digest is printed, and not a float, whose hexadecimal form nothing in Snello writes. The zero flag pads a number with zeros after its sign, and the checker refuses it on anything else, where Go pads a string with zeros; the minus flag overrides it, and so does a precision on an integer, as in Go. A width and a precision are a million at most, the bound Go's `fmt` holds one to when it is an argument, printing `%!(BADWIDTH)` or `%!(BADPREC)` past it, and since Snello's is written in the format the checker refuses a larger one, as Rust's compiler refuses one past its own bound of 65535 (when the grammar read any number of digits into an `int`, `%.99999999999999999999f` wrapped to nine digits, and a precision past 32 bits reached the runtime as a negative size); the runtime holds a precision to the same bound, so that its memory rests on no check but its own. The verbs a string takes, `%v`, `%s`, `%q`, `%x` and `%X`, print through a `String` or `Error` method whatever the type is declared over, and every other verb prints the value itself, which is Go's rule: `%x` of a type with a `String` is the bytes of what it returns, and `%g` of a float type with one is the float; the zero flag is refused on `%v`, `%x` and `%X` of a number that prints as text, which is no number. Of Go's other flags `+` is taken by an error's chain (decided 11) and `#` and the space stay out: a prefix is written in the format, `0x%x`. `%T` and `%p` stay out, since there is no reflection and a pointer prints as its value, and `%U`, `%E` and `%G` until a program needs one. A float's exponent is written by hand (when `%e` and the shortest form wrote it with the C library's `snprintf`, that call was 45% of the time of printing a float with an exponent, 0.31 s for five million against Go's 0.24 s; 0.24 s without it). Since the compiler reads the format, the checker checks it against the arguments, as `go vet` does, but as an error: one grammar, `compiler/types/format.go`, serves the checker and both backends, which import the checker's package already. A type prints through its `String` method when it lists the trait `fmt.Stringer` after `impl`; Go matches `String() string` structurally, and a Snello trait is named, so the trait is declared in `std/fmt` and a type opts in, as it does for `Error`. `strconv.Error` has `Kind()`, `Syntax`, `Range` or `Base`, read from its message, Go's `ErrSyntax` and `ErrRange` and the base Go reports without a name; `ParseFloat` reads Go's grammar, underscores and hexadecimal floats with their `p` exponent included. The predeclared `min` and `max` answer `NaN` when an argument is `NaN` and take `-0` as below `+0`, as Go's specification has them, where `math.Min` and `math.Max` keep Go's own order of special cases. `ParseFloat`, `Atoi` and `Unquote` take text a program does not control, and each has a fuzz test, `std/std_test.go`: Go's fuzzer asks a Snello program, built with the runtime's checks, what the library makes of a text and holds the answer to Go's `strconv`'s for the same text, so that the library is exercised as a program reaches it and the fuzzer is steered by the coverage of the reference. No job in CI runs them: a campaign is run by hand, ten minutes a function, and an input it finds is fixed and kept as a seed of the fuzz test and a case of the package's tests.

**Decided 7: what the standard library leaves out.** The library is small on purpose and stays so: the goal decided is a lean core that is rock solid, with every other library built outside the compiler on that core, as Rust's crates are built on its `std`. The rule is Rust's: a package joins the standard library when the language or the runtime needs it, `fmt`, `io`, `os`, `sync`, `time`, `net`, the collections, `arena` and `rc`, or when every program would otherwise write it, `strings`, `strconv`, `sort`, `heap`, `bufio`, `bytes`, `path`, `math`; a package that encodes a format, speaks a protocol or talks to a service stays out, so `regexp`, `json`, `db` and `net/http` never join, where Go ships the first three. A package that stays in is held to the industry's reference implementation and measured against Go's and Rust's before it is done, as every row of the table above records. What makes the rule honest is that a library outside the compiler can be written at all, which needs packages of the program's own and a way to bind C, the subject of `08-packages.md`; `regexp` is to be written under `lib/` as the proof, and any gap it meets is a gap in the core, not a reason to move it in.

**Decided 8: the state-machine example moves to `net`, not `net` to the example.** The state machine's sketch named a `net.Socket` and a `net.Dial("...")` with no address and no way to fail, which no library has: Go's `Dial` takes an address and returns an error, and so does this package's, `Dial(host, port)` returning a `Result<Conn, io.Error>`, and it needs a peer listening. Widening the package for a sketch would go against decision 7, so the example opens a `net.Listen` on a port the system picks, dials it, and its `Session` owns the `net.Conn`; once the state that held the session is dropped, the listener's accepted side reads the end of the connection, which shows the point the example makes, that a socket closes where its state goes. The package is unchanged.

**Decided 9: the cache-server example serves over `net`, and its three checker errors were the sketch's.** The sketch imported `net/http`, `db` and `json`, which the library does not have and decision 7 keeps out, read the map through `c.Get()[ref id]` bound as an option, called `sync.Arc.New`, and was expected to fail on `sync.NewArc(sync.NewRwLock(map[string]Entry{}))`, a nested generic call whose argument the checker would not infer. Against the library as written each settles on the example's side and changes nothing in the library: a map's `Get` lends `ref V?`, which an `if` binding takes, while `m[k]` is the read that gives the zero value; `sync.NewArc` is the constructor, as `rc.New` is; and the checker infers the outer call's argument from the inner call's result, as it does for every nested call. The program is a server over a port it prints on standard error, speaking `GET key`, `SET key value`, `QUIT` and `SHUTDOWN` a line at a time, a task per connection holding a clone of an `Arc<RwLock<map>>`, a `GET` under the read lock and a `SET` under the write lock for the one request, and a `Session` whose `Drop` reports the close before the connection's own `Drop` closes the socket, so that the report is on standard output when the client sees the end, which is what lets the suite compare it. The accept loop watches for the stop with a deadline of a tenth of a second on `Accept` and a `select` with a `default`, since there is no select over sockets; a server that stops on a signal is the shape `net` serves today. The suite drives the program with a script beside it, `examples/cache-server/cache-server.script`, a section per connection of lines sent and replies expected, the convention for any example that serves.

- **A `ref T` is a copy of `T` in the compiled program**, not a pointer, which is what makes a borrow of a small value free and a borrow of a pointer the pointer itself. So a lock cannot hold its value inline: `Lock` on a `ref Mutex<T>` would reach a copy of the value, and a change through the guard would be lost. `Mutex<T>` and `RwLock<T>` therefore hold a box on the heap, the lock's handle and the value, as `rc.Rc` holds its cell; every borrow of the lock copies the box's address and reaches the one box.
- **A handle holds its cell by address, and the steps the language refuses elsewhere are lowered functions.** An `Arc`, an `rc.Rc` and an `rc.Weak` hold the address of a cell no one handle owns, `cell int`, freed by the handle the counts say is last; a `Mutex` and an `RwLock` hold the address of the box they own alone, `box int`, freed by their `Drop`. Beside it each holds a zero-length array of pointers to the cell's or the box's type, `cellType [0]*acell<T>` or `boxType [0]*box<T>`, which holds nothing: the type it names is what the compiler reads to decide whether the handle is `Send`, and the pointer is what lets a value hold a handle on a cell of its own type. `rawNew` moves a cell or a box into a block of its own; `rawMut` lends it at an address for as long as the handle is lent, its fields read in place and never the whole block copied, the one place in the language a `mut` comes from a `ref`: the value changed only under the lock, `sync`'s count only by an atomic add, and `rc`'s counts plain, since its cell stays in one task; `rawTake` moves the cell or the box out and frees the block, for the last `Arc` and for a lock's `Drop`; `rc` adds `rawFree`, for a cell whose value went with its last `Rc` while `Weak`s remain, `moveOut`, which moves the value out of the cell when the strong count reaches zero, and `leak`, which gives an `Rc` up without its `Drop` once `TryUnwrap` has spent its count. The compiler writes them by package and name, for `rc` and `sync` alone. They replaced an optional pointer in each handle, whose empty state no handle ever reached and which left every `Get`, `Lock`, `Read` and `Write` a branch with a panic in it: a handle now has no empty state, so none of them has the branch, and since a program cannot call a `Drop` by hand, no handle outlives its cell.
- **A guard is a borrow-holding struct with a `Drop`.** `Lock` and `Write` return `Guard<T>`, which holds the lock's handle and a `mut T`; `Read` returns `ReadGuard<T>` with a `ref T`. Both are tied to the lock they came from under the rules of `04-borrows-ref-and-mut.md`, so they cannot be stored, sent or outlive the lock, and `g := m.Lock().Get()` is refused as a borrow of a temporary. Their `Drop` gives the lock back. The value is reached through `Get`, as it is on `rc.Rc` and `arena.Arena`: `*g.Get() += 1` changes a number, `g.Get().Push(v)` a slice. A guard whose fields are the borrow was tried first, written `*g.v`, and set aside for the method, so that the three packages read alike.
- **A runtime lock is held as an `int`, as a file is.** The runtime's handle on a lock, its address, is a Snello `int`, so the library holds a handle the language can write and the runtime's structure stays its own; a `Mutex` or `RwLock` frees its lock in `Drop`, and a `WaitGroup`'s lock is freed by the last handle on the `Arc` it shares. A lock is the runtime allocator's, so a debug build reports one that nothing freed. One runtime object serves all three: a lock held exclusively or shared, with a count for the wait group, and the list of waiting tasks the channels use, so the scheduler parks a task on a lock as it parks one on a channel (`06-tasks-and-channels.md`).

The constructors are `NewArc`, `NewMutex`, `NewRwLock`, `NewOnce` and `NewWaitGroup`, since Snello has no function on a type, only methods on values: `sync.Arc.New(v)` as the examples first wrote it is not a form the language has. None of these types has a zero value (the zero values of the syntax note): each implements `Drop` or holds a type that does, so a handle comes only from its constructor, and the empty-handle panics they had, as `rc.Rc`'s had, cannot be reached; a `Once` is a `Mutex<bool>` and is made the same way. `Arc<T>` counts with one atomic add the runtime provides, on the cell's own field through `rawMut`, and needs no lock. `time.After` and `time.Tick` are written in Snello as a task that sleeps and sends on a channel of one, with `Tick` dropping a tick its receiver has not taken.

## The core library table

Before the library was written in Snello, a table in the C emitter mapped each library name onto a function of the C runtime with the same meaning. What remains of it is the methods of section 1 on slices, maps, strings, options and results, each a runtime function, and the lowering of the seven functions the compiler provides. Library code written in Snello is the same for both backends.

## What this does not decide

Which functions exist beyond the ones above. The twenty examples are the specification for that: every function the examples call exists with the signature the examples use.

**Decided 10: `sync.Counter` and `sync.Atomic<T>`, and the standard streams as functions.** A package variable changes only through what it holds (`03-ownership-across-tasks.md`, package variables), so the package gained the two holders beside the locks: `Counter`, an `int` in one word of the runtime's with `Add`, `Load`, `Store` and `CompareAndSwap` as single instructions, and `Atomic<T: Send + Clone + Eq>`, any value read and replaced as one step under a lock the `Atomic` owns, decided that an atomic holds anything; a hardware `Atomic<T>` over the integer widths, with an `Integer` bound and conversions on a type parameter, was built first and taken out again as the larger surface for no gain the measurement showed: ten million increments on an eight-core arm64 laptop cost 7 ns each through the word from one task and 17 ns with two tasks contending, against 10 ns and 10 to 13 ns through `Mutex<int>`. `os.Stdin`, `os.Stdout` and `os.Stderr` became functions giving a fresh handle on the descriptor, since `Read` and `Write` take `mut` and a package variable is never lent one; of the four ways weighed the function changes nothing in `io`, `fmt` or `bufio` and adds a pair of parentheses to eighteen places.

**Decided 11: the `Error` trait, whole, and no `errors` package.** Go's `errors` and `fmt.Errorf("%w")` and Rust's `thiserror` exist to write by hand what the language can do once a type says it is an error, so the trait does the three things a program otherwise writes, and the library gains no package for them.

- **`Source() Error?` is the trait's second method, and its default is none.** `trait Error { func (s ref Self) Error() string; func (s ref Self) Source() Error? }`. A type that wraps another error writes `Source` to give it; a type that writes none has the method derived, as `Eq` and `Clone` are derived, and it gives `None`. The result is an owned trait value, a clone of the cause or a fresh one, since a trait value owns its data and a borrowed trait value is still not a type; the cost is one allocation per call on the error path, which is where it is paid. Rust's `source()` lends `&dyn Error` for the same purpose; the owned form changes nothing in the rules of chapter 6 and needs no new type. Nothing in the library wraps today, so `io.Error` and `strconv.Error` write no `Source`; `strconv.Error` lists `Clone`, as `io.Error` did already, so that a program's error may hold either and give it through its own `Source`.
- **An enum or a struct that lists `Error` and writes no `Error()` has it derived: the message is the value as `%v` prints it.** `Unreadable("open app.conf: no such file or directory")` for a variant holding an `io.Error`, `NotFound("app.conf")` for one holding a path, `Missing` for one holding nothing. One rule, the printing rule the language has already, and no second grammar for messages: a program that wants Go's wording writes `Error()` as before, and a program that wants a quick error lists the trait and moves on. The derivation is refused, at the declaration, for a field the language cannot print, a function value or a trait value of another trait, with the field named: `E does not implement Error: field f has type func(), which cannot be printed`.
- **`?` passes an error on wherever an assignment would take it, and into the one variant that holds its type.** In a function returning `Result<T, E>`, `x?` on a `Result<U, F>` returns `Err` of: the error itself when `F` is `E`; a trait value holding it when `E` is a trait `F` implements, so `Result<T, Error>` is Go's `(T, error)` and an `io.Error` or a `strconv.Error` passes into it with nothing written; and the variant when `E` is an enum with exactly one variant whose only field has type `F`, so `Unreadable(cause io.Error)` takes an `io.Error` the way Rust's `From` does, without the implementation written. Two such variants are ambiguous and refused, `? cannot pass on an error of type io.Error from a function returning Result<Config, ConfigError>: ConfigError holds an io.Error in Read and in Write; convert it`, and none is refused as today with the reason added, `: no variant of ConfigError holds an io.Error`. Nothing else converts: `return Err(e)`, `MapErr` and a `match` stay as they are, and a conversion is never more than one step. The rule is decided here and recorded beside the other rules of `?` in `00-syntax-conventions.md`.
- **`%+v` prints the chain: the message, then each source's message after a colon and a space.** `read config: open app.conf: no such file or directory` for an error whose `Source` is the `io.Error`, and the same as `%v` for an error with no source. The flag goes with `v` only and only on a value that implements `Error` or a trait value of it; the checker refuses it anywhere else, `fmt takes the + flag on %v of an error only`, since the language checks formats and a flag that is quietly `%v` on everything else would hide a mistake. Go's `%+v` is a different thing, field names on a struct, which Snello does not have and `%v` does not need.
- **A trait value of `Error` or of `fmt.Stringer` prints as its message**, through its table, where any trait value was refused before; `fmt.Println(e)` on a `Result<T, Error>`'s error is the first thing a Go programmer writes. A trait value of any other trait is still refused.

The alternatives weighed. A `Source` that is derived from the one field of a variant that implements `Error`, with the derived message leaving that field out, prints `Unreadable` for the common case and makes `%+v` the only way to read a converted error, so the message carries the cause and `Source` stays none unless written. An `errors` package with `New`, `Is` and `Wrap` would be Go's, and two of its three are a type's own business here: `Is` is a `match` on the enum, and `Wrap` is a variant. An `Error()` derived with the variant's name split into words, `not found: app.conf`, is a second printing rule for a prettier line and was not taken.

**Decided 12: runes.** A string stays immutable UTF-8 bytes, with `len(s)` and `s[i]` in bytes since both are constant time; what was missing is the rune, the code point, of type `rune`, an `i32`.

- **A range over a string yields runes.** `for i, r := range s` gives each rune and the byte offset it starts at; `for i := range s` the offsets alone. The string is lent for the loop, as `range s.Fields()` lends it. A byte that does not start a valid UTF-8 sequence yields U+FFFD and the loop moves on one byte, the one rule of the runtime's decoder that `ToUpper`, `Fields` and `%q` follow already, so every part of the language reads a broken string the same way. The rule is recorded in `00-syntax-conventions.md`. A loop over the bytes is the counted loop, `for i := 0; i < len(s); i++ { s[i] }`, with no allocation. Why runes: a string is text, and walking text a byte at a time is right only for ASCII, so the loop that is easiest to write is the one that is right for every language; indexing stays in bytes because it is constant time, and the book says so beside the range. No program ranged over a string before this decision, so none changes meaning. Two alternatives were weighed. No range over a string at all, with `s.Runes()` and a byte iterator to choose from, as Rust makes the choice explicit, costs a method and an iterator type on every loop for the case that is almost always meant. A range over grapheme clusters, what a reader sees as one character, as Swift's does, needs Unicode's segmentation tables and rules, and is a package's work if a program needs it, not the loop's.
- **`s.Runes() []rune`**, an owned slice of the runes, for a program that must index them, and **`string(rs)` and `string(r)`**, the conversions back, a value that is not a code point written as U+FFFD. Only a `rune` converts to a string: `string(65)`, which means `"A"` where it is allowed and is a common mistake for `"65"`, is refused, decided with the review of the task.
- **`strings.Builder.WriteRune(r rune)`** appends the rune's UTF-8 bytes, and U+FFFD for a value that is not a code point. **`bufio.Reader.ReadRune()`** returns `Result<(rune, int)?, io.Error>`, the rune and its width in bytes, `None` at the end, as `ReadByte` returns `Result<byte?, io.Error>`; a byte that does not start a valid sequence reads as U+FFFD of width one.
- **The `unicode` package**: `IsLetter`, a rune of category L; `IsDigit`, category Nd; `IsSpace`, Unicode's `White_Space` property, the table `Fields` and `Trim` use; `IsUpper`, category Lu; `IsLower`, category Ll (both changed by decided 13 to the derived `Uppercase` and `Lowercase` properties); `IsPrint`, a letter, mark, number, punctuation or symbol or the ASCII space, the table `%q` uses; `ToUpper` and `ToLower`, the simple case mapping `strings.ToUpper` uses. Each is a function over the runtime's tables, which `runtime/mkunicode.go` writes from Unicode's own files, `UnicodeData.txt` and `PropList.txt` at 18.0.0; the categories are new tables of runs beside the case and space tables, searched by halving. A test checks every one of the 1,114,112 code points against the same files, which are checked in under `runtime/testdata/ucd/18.0.0/` so that the test reads them offline; the meaning of each function is Unicode's, not another language's.
- **The `unicode/utf8` package**: `RuneError`, U+FFFD; `RuneLen(r) int`, the bytes the rune takes, or -1 for a value that is not a code point; `AppendRune(p mut []byte, r rune)`, which appends the encoding, named apart from an encoder writing into a buffer of fixed size since the slice grows instead; `DecodeRune(p ref []byte) (rune, int)` and `DecodeRuneInString(s ref string) (rune, int)`, the first rune and its width, `(RuneError, 1)` for a byte that does not start a valid sequence and `(RuneError, 0)` for empty input. It is the library's first package two levels deep, so the embedded library and the importer take a path of two elements, `unicode/utf8`, under `std/unicode/utf8/`.
- **The book** gets a chapter of its own for text, `19. Text: strings, runes and Unicode`, for developers and maintainers, and chapters 3, 9 and 14 point at it.

**Decided 13: Unicode, whole.** Decided 12 gave the rune; this finishes the subject, since the library is complete per subject. The subject is Unicode text: its encodings, its character properties, its case, its normalization and its segmentation.
